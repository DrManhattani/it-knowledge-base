# Команда git add

> [!ABSTRACT] **Суть команды**
> 
> **git add** — это команда, которая переносит изменения из Рабочей директории в **Индекс (Staging Area)**. Это позволяет тебе «курировать» будущий коммит, выбирая только нужные правки.

---
### 🔩 Что происходит под капотом (Pro-уровень)

Многие думают, что объекты **blob** создаются во время `git commit`. На самом деле вся тяжелая работа происходит именно во время `git add`:

1. **Хеширование:** Git берет контент файла и вычисляет его **SHA-1 хеш**.
2. **Создание Blob:** Git немедленно упаковывает контент файла в объект типа **blob** и сохраняет его в базу данных `.git/objects`.
3. **Обновление Индекса:** Git обновляет файл `.git/index`, записывая туда путь к файлу и его новый хеш.

> [!TIP] **Инсайт для интервью:**
> 
> Если ты сделаешь `git add`, но потом передумаешь и удалишь файл, не сделав коммит, — **твой контент всё равно останется в базе** `.git/objects` в виде «висячего» (dangling) блоба, пока его не почистит сборщик мусора (`git gc`).

### 🛠️ Таблица флагов `git add`

| **Флаг**          | **Описание**                                                                                              | **Пример**           |
| ----------------- | --------------------------------------------------------------------------------------------------------- | -------------------- |
| `.`               | Добавляет всё: новые файлы и изменения в текущей папке и подпапках.                                       | `git add .`          |
| `-u` (`--update`) | Добавляет только изменения в **уже отслеживаемых** файлах и удаления. Не трогает новые (untracked) файлы. | `git add -u`         |
| `-A` (`--all`)    | Комбинация `.` и `-u`. Добавляет вообще всё: новые, измененные и удаленные файлы во всем репозитории.     | `git add -A`         |
| `-p` (`--patch`)  | **Интерактивный режим.** Позволяет просмотреть каждый кусок (hunk) кода и выбрать, добавлять его или нет. | `git add -p`         |
| `-f` (`--force`)  | Позволяет принудительно добавить файлы, которые прописаны в `.gitignore`.                                 | `git add -f log.txt` |
| `-n (dry-run)`    | Покажет, какие файлы будут добавлены, но не добавит их                                                    | `git add -n`         |

### ❓ Потенциальные вопросы на собеседовании

> [!question] 1. В чем разница между `git add .` и `git add -A`?**
> - **Ответ:** В современных версиях Git они почти идентичны. Однако `git add .` работает относительно текущей папки, а `git add -A` (или `git add /`) всегда захватывает весь репозиторий, даже если ты находишься в глубокой подпапке.

> [!question] 2. Зачем нужен флаг `git add -p`?
> - **Ответ:** Это лучший способ делать «чистые» коммиты. Если я поправил баг и случайно оставил `console.log`, с помощью `-p` я могу добавить только исправление бага, пропустив ненужные строки.

> [!question] 3. Что произойдет, если я сделаю `git add`, а потом изменю файл еще раз до коммита?
> - **Ответ:** В Индексе останется та версия файла, которая была на момент выполнения `git add`. Чтобы зафиксировать новые правки, нужно выполнить `add` повторно.

> [!question] 4. Можно ли отменить `git add`?
> - **Ответ:** Да, с помощью команды `git restore --staged <file>` (в новых версиях) или `git reset HEAD <file>` (в старых). Это уберет файл из Индекса, но оставит твои правки в рабочей директории.
