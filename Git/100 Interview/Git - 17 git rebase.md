# 🏗️ git rebase: Архитектура «Переписывания Прошлого»

### ⚙️ Что происходит под капотом (Алгоритм)

Когда ты запускаешь `git rebase <target>`, Git выполняет сложную последовательность низкоуровневых операций:

1. **Поиск Merge Base:** Находится ближайший общий предок текущей ветки и целевой ветки (target).
    
2. **Сбор патчей:** Все коммиты текущей ветки, сделанные после общего предка, преобразуются во временные файлы-патчи (в каталоге `.git/rebase-apply/`).
    
3. **Сброс указателя:** Указатель текущей ветки принудительно перемещается (Reset) на последний коммит целевой ветки.
    
4. **Воспроизведение (Replay):** Патчи применяются по одному в хронологическом порядке к новому состоянию ветки.
    - Для каждого патча создается **новый объект коммита**.
    - Даже если код не изменился, у коммита меняется **родитель (parent)**, а значит, и **SHA-1 хеш**.
5. **Очистка:** Удаляются временные файлы, и `HEAD` обновляется.

### 🧪 20 Профессиональных Вопросов для Собеседования

Я разбил их по уровням, чтобы ты мог прочувствовать градацию от «пользователя» до «инженера».

#### 🟢 Уровень: Junior+ (База)

1. **В чем фундаментальное отличие `rebase` от `merge`?**
    
    - _Ответ:_ Merge создает новый коммит-узел, сохраняя историю обеих веток. Rebase переносит коммиты, создавая линейную историю.
        
2. **Что такое "Золотое правило ребейза"?**
    
    - _Ответ:_ Никогда не делать `rebase` веток, которые уже запушены в общий репозиторий. Это сломает историю коллегам.
        
3. **Меняется ли хеш коммита при ребейзе?**
    
    - _Ответ:_ Да, всегда. Даже если содержимое файлов идентично, меняется ссылка на родителя и дата коммита.
        
4. **Что происходит с конфликтами во время ребейза?**
    
    - _Ответ:_ Они решаются пошагово для каждого переносимого коммита, а не один раз для всего слияния.
        
5. **Как отменить неудачный ребейз, если ты еще не закончил?**
    
    - _Ответ:_ `git rebase --abort`.
        

#### 🟡 Уровень: Middle (Инструментарий)

6. **Что делает флаг `-i` (Interactive)?**
    
    - _Ответ:_ Позволяет редактировать список коммитов перед их применением (объединять, удалять, изменять порядок).
        
7. **Разница между `squash` и `fixup` в интерактивном режиме?**
    
    - _Ответ:_ Оба объединяют коммиты, но `squash` просит отредактировать сообщение коммита, а `fixup` просто выкидывает сообщение вливаемого коммита.
        
8. **Что такое `git pull --rebase` и зачем он нужен?**
    
    - _Ответ:_ Это `fetch` + `rebase` локальной ветки поверх удаленной. Позволяет избежать "Merge branch 'main' of..." коммитов.
        
9. **Как продолжить ребейз после исправления конфликта?**
    
    - _Ответ:_ `git add <file>` (чтобы пометить конфликт решенным) и `git rebase --continue`.
        
10. **Можно ли сделать ребейз не на ветку, а на конкретный хеш?**
    
    - _Ответ:_ Да, аргументом может быть любая ссылка (ветка, тег, хеш).
        
11. **Что будет, если во время ребейза коммит станет «пустым» (те же изменения уже есть в базе)?**
    
    - _Ответ:_ Git пропустит его автоматически или попросит подтвердить пропуск через `git rebase --skip`.
        

#### 🔴 Уровень: Senior/DevOps (Хардкор)

12. **Что такое `git rebase --onto`? Приведи пример.**
    
    - _Ответ:_ Это "хирургический" ребейз. Позволяет взять кусок ветки `A`, который начался от ветки `B`, и пересадить его на ветку `C`, игнорируя изменения из `B`.
        
13. **Как восстановить ветку, если ты сделал `rebase` и всё потерял, а `--abort` уже поздно?**
    
    - _Ответ:_ Использовать `git reflog`, найти хеш ветки до начала ребейза и сделать `git reset --hard <hash>`.
        
14. **Как `rebase` взаимодействует с хуками (hooks)?**
    
    - _Ответ:_ При ребейзе на каждый коммит может триггериться `post-commit` хук, но чаще всего проблемы возникают с `pre-rebase`.
        
15. **Что такое "Conflict Storm" при ребейзе?**
    
    - _Ответ:_ Ситуация, когда ты переносишь 50 коммитов, и на каждом втором возникает один и тот же конфликт. Решение: использовать `git rerere`.
        
16. **Как работает механизм `git rerere`?**
    
    - _Ответ:_ Reuse Recorded Resolution. Git запоминает, как ты решил конфликт в куске кода, и при следующем возникновении такого же конфликта применяет решение автоматически.
        
17. **Почему `rebase` может быть опасен для CI/CD пайплайнов?**
    
    - _Ответ:_ Если пайплайн завязан на хеши или теги, переписывание истории заставит пайплайны запускаться заново или падать из-за несовпадения версий.
        
18. **В чем разница между `git rebase` и `git cherry-pick`?**
    
    - _Ответ:_ Cherry-pick копирует конкретный коммит в текущую ветку. Rebase переносит всю последовательность от общего предка.
        
19. **Как сделать интерактивный ребейз для самого первого коммита в репозитории?**
    
    - _Ответ:_ `git rebase -i --root`.
        
20. **Можно ли автоматически делать авто-сквош (`autosquash`) при ребейзе?**
    
    - _Ответ:_ Да, если создавать коммиты через `git commit --fixup=<hash>`, а потом запускать `git rebase -i --autosquash`. Git сам расставит команды `fixup` в списке.
