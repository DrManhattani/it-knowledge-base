# 📖 Руководство: Git Branch

### 1. Техническое определение

**git branch** — это инструмент для управления **указателями на коммиты**.

С технической точки зрения, ветка в Git — это просто **текстовый файл** весом 41 байт, который хранится в директории `.git/refs/heads/`. В этом файле записан 40-символьный SHA-1 хеш коммита, на который она указывает, и символ переноса строки.

> [!QUOTE] **Инженерный инсайт**
> 
> Создание ветки в Git не зависит от размера проекта. Будь у тебя 1 файл или 1 миллион, создание ветки — это просто создание крошечного текстового файла. Это происходит мгновенно ($O(1)$).

---

### 2. Работа «под капотом»: Анатомия указателей

Чтобы понять, как Git ориентируется в пространстве, нужно различать три сущности:

1. **Указатель ветки (Branch Ref):** Именованная ссылка на последний коммит в данной линии разработки (например, `main` или `feature`).
2. **HEAD:** Специальный указатель, который говорит Git, на какой ветке (или коммите) ты находишься прямо сейчас. Он хранится в `.git/HEAD`.
3. **Удаленная ветка (Remote Tracking Branch):** Указатель на последнее известное состояние ветки на сервере (например, `origin/main`). Ты не можешь двигать его напрямую, он обновляется только при `fetch` или `push`.

### 4. Нюансы и "Черная магия"

#### Состояние "Detached HEAD"

Это ситуация, когда `HEAD` указывает не на имя ветки, а напрямую на хеш коммита.

- **Как попасть:** `git checkout <hash>`.
- **В чем риск:** Если ты сделаешь коммиты в этом состоянии, а потом переключишься на другую ветку, эти коммиты станут «сиротами». У них не будет имени ветки, которое бы их удерживало, и со временем их удалит Garbage Collector (`git gc`).

#### Где живут удаленные ветки?

Они лежат в `.git/refs/remotes/`. Гит разделяет их, чтобы ты мог работать автономно. Когда ты делаешь `git branch`, ты видишь свои локальные копии, но флаг `-r` покажет тебе «снимки» сервера.

### 5. Вопросы с собеседований

#### 🟢 Junior (База)

- **Как создать ветку и сразу переключиться на неё?**
    
    - _Ответ:_ `git checkout -b <name>` или современная команда `git switch -c <name>`.
        
- **В чем разница между `git branch -d` и `git branch -D`?**
    
    - _Ответ:_ `-d` — это предохранитель, он не даст удалить ветку с неслитыми данными. `-D` — это принудительное удаление без проверок.

#### 🟡 Middle (Инструментарий)

- **Что происходит с коммитами при удалении ветки?**
    
    - _Ответ:_ Коммиты не удаляются мгновенно. Удаляется только указатель (файл в `refs/heads`). Сами объекты коммитов остаются в базе, пока не сработает сборщик мусора. Их можно восстановить через `reflog`.
        
- **Как переименовать ветку на сервере (remote)?**
    
    - _Ответ:_ Прямой команды нет. Нужно переименовать локально, удалить старую ветку на сервере (`git push origin --delete old`) и запушить новую (`git push origin new`).
#### 🔴 Senior (Архитектура)

- **Как восстановить случайно удаленную ветку, если ты не помнишь хеш последнего коммита?**
    
    - _Ответ:_ Нужно заглянуть в `git reflog`. Там хранятся все перемещения `HEAD`. Найдя последнюю точку на удаленной ветке, можно сделать `git branch <name> <hash>`.
        
- **Как программно проверить, является ли одна ветка предком другой?**
    
    - _Ответ:_ Использовать низкоуровневую команду `git merge-base --is-ancestor <commit> <commit>`. Она вернет 0, если первая является предком второй.
