# Команда git status

> [!ABSTRACT] **Определение**
> 
> **git status** — это главный инструмент для отслеживания изменений в репозитории Git. Она показывает разницу между тремя «деревьями» Git: **HEAD** (последний коммит), **Index** (область подготовки) и **Working Directory** (твои файлы). Основной инструмент, используемый для определения, какие файлы в каком состоянии находятся

---
### 🛠️ Популярные флаги и примеры

> [!INFO] **Таблица наиболее используемых флагов**

| **Флаг**      | **Полное имя**      | **Описание**                                                                                                             | **Пример команды**       |
| ------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------ |
| `-s`          | `--short`           | **Короткий формат.** Выводит статус в две колонки. Левая — состояние индекса, правая — состояние рабочего дерева.        | `git status -s`          |
| `-b`          | `--branch`          | **Информация о ветке.** Показывает текущую ветку и её отношение к удаленной (на сколько коммитов опережаем/отстаем).     | `git status -sb`         |
| `-u`          | `--untracked-files` | **Управление неотслеживаемыми файлами.** Параметр `no` скрывает их, `all` показывает каждый файл внутри новых папок.     | `git status -uno`        |
| `--ignored`   | `--ignored`         | **Показать игнорируемое.** Выводит список файлов, которые обычно скрыты правилами из `.gitignore`.                       | `git status --ignored`   |
| `--porcelain` | `--porcelain`       | **Машинный формат.** Аналог `-s`, но гарантирует стабильность формата вывода. Используется для автоматизации и скриптов. | `git status --porcelain` |

### ❓ Потенциальные вопросы на собеседовании

> [!question] 1. "Видит" ли `git status` изменения в удаленном репозитории (GitHub/GitLab)?
> **Ответ:** **Нет.** Это исключительно локальная команда. Она сравнивает только твои локальные области. Чтобы `status` показал, что ты отстал от сервера, нужно сначала сделать `git fetch`.

> [!question] 2. Что произойдет, если изменить файл, сделать `git add`, а затем снова изменить его, не делая коммит?
> **Ответ:** `git status` покажет этот файл **в двух секциях одновременно**:
> 
> - В `Changes to be committed` (зеленым) — версия файла на момент первого `add`.
>     
> - В `Changes not staged for commit` (красным) — новые правки, которые еще не попали в индекс.
>     

> [!question] 3. В чем техническая разница между "Untracked" и "Ignored" файлами?
> **Ответ:** > * **Untracked:** Новые файлы, о которых Git знает, что они есть в папке, но не следит за ними.
> 
> - **Ignored:** Файлы, которые мы явно приказали Git игнорировать (через `.gitignore`). Они не отображаются в обычном статусе и не попадают в репозиторий.
>     

> [!question] 4. Как с помощью `status` понять, что в репозитории есть конфликт слияния?
> **Ответ:** В выводе появится секция **"Unmerged paths"**. Файлы с конфликтами будут помечены как `both modified`.

### 💡 Пример вывода (Краткий формат `-s`)

При выполнении `git status -s` ты можешь увидеть такие маркеры:

- ` M` (пробел перед M) — файл изменен только в рабочей директории.
- `M ` (M в первой колонке) — файл изменен и добавлен в индекс (`git add`).
- `MM` — изменен, добавлен в индекс, и после этого снова изменен.
- `??` — новый (untracked) файл.
