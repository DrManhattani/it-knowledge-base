# Команда git diff

> [!ABSTRACT] **Определение**
> 
> **git diff** — сравнивает изменения между различными состояниями файлов в репозитории. Показывает разницу между файлами в рабочей директории, индексом или коммитом. 
> - Чаще всего она используется для просмотра изменений, которые ты внес в код, но еще не закоммитил. Она сравнивает содержимое файлов построчно, используя алгоритмы поиска минимальной разницы.

### 🛠️ Популярные флаги и примеры

| ------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| **(нет)**     | `git diff`           | **Unstaged changes.** Показывает разницу между рабочей директорией и Индексом (Staging). То, что ты изменил, но ещё не сделал `git add`.                                                                 | `git diff`             |

| `HEAD`        | `HEAD`               | **Все изменения.** Показывает разницу между рабочей директорией и последним коммитом.                                                                                                                    | `git diff HEAD`        |
| `--stat`      | `--stat`             | **Статистика.** Вместо кода показывает краткую сводку: какие файлы изменились и сколько строк добавлено/удалено.                                                                                         | `git diff --stat`      |
| `--name-only` | `--name-only`        | **Только имена.** Выводит просто список изменившихся файлов. Идеально для скриптов.                                                                                                                      | `git diff --name-only` |
| `-w`          | `--ignore-all-space` | **Игнорировать пробелы.** Полезно, если ты просто поправил отступы в коде и не хочешь видеть это в диффе.                                                                                                | `git diff -w`          |

### ⚙️ Как это работает «под капотом»

На собеседовании уровня «Инженер» важно понимать механику. Git не хранит «разницу» между файлами, он хранит **снимки (snapshots)**.

1. **Сравнение блобов (Blobs):** Когда ты запускаешь `diff`, Git берет идентификаторы объектов (SHA-1 хеши) файлов из двух разных состояний (например, из рабочей директории и индекса).
2. **Алгоритм:** Если хеши разные, Git запускает алгоритм (обычно это _алгоритм Майерса_), который ищет кратчайший путь трансформации одного текста в другой.
3. **Формат вывода (Unified Diff):**
    - `--- a/file` — старая версия.
        
    - `+++ b/file` — новая версия.
        
    - `@@ -1,4 +1,4 @@` — **чанк (chunk)**. Координаты изменений: откуда и сколько строк изменилось.
        
    - `-` — строка удалена.
        
    - `+` — строка добавлена.

### ❓ Потенциальные вопросы на собеседовании

> [!question] 1. В чем разница между `git diff` и `git diff --staged`?
> 
> **Ответ:** Это самый частый вопрос. Обычный `git diff` сравнивает **рабочую директорию с индексом** (показывает, что ты еще не добавил через `add`). А `--staged` (или `--cached`) сравнивает **индекс с последним коммитом** (показывает, что попадет в коммит, если ты прямо сейчас введешь команду `commit`).

> [!question] 2. Как сравнить одну и ту же ветку, но в состоянии "сейчас" и "три коммита назад"?
> 
> **Ответ:** Можно использовать ссылку `HEAD~3`: `git diff HEAD~3 HEAD`. Или просто сравнить по хешам коммитов: `git diff <sha1> <sha2>`.

> [!question] 3. Можно ли с помощью `diff` сравнить только один конкретный файл?
> 
> **Ответ:** Да, нужно просто указать путь к файлу после команды: `git diff path/to/file.txt`. Это работает со всеми флагами.

> [!question] 4. Как сравнить изменения между двумя ветками?
> 
> **Ответ:** Используется синтаксис с двумя точками: `git diff main..feature-branch`. Это покажет разницу между кончиками двух веток.

> [!question] 5. Что такое "трехточечный дифф" (`git diff main...feature`)?
> 
> **Ответ:** Это хитрый вопрос. `...` (три точки) показывает изменения в ветке `feature` с того момента, как она **ответвилась** от `main`. Это игнорирует новые коммиты в `main`, которые появились после создания ветки.

### 💡 Лайфхак для терминала

Если ты работаешь в Linux-консоли, стандартный вывод `diff` бывает трудно читать. Настрой себе **цветной дифф** одной командой:

`git config --global color.ui true`

Или используй внешний инструмент, если он установлен (например, `delta` или `diff-so-fancy`).
