# ➕ git add

> [!ABSTRACT] Суть
> Команда переводит файлы из статусов **Untracked** и **Modified** в статус **Staged**. Технически, в этот момент Git вычисляет хеш контента и сохраняет его в базе объектов.

---

> [!INFO] 🔍 1. Основные способы добавления
> | № | Команда | Описание |
> | :-- | :--- | :--- |
> | 1 | `git add <file>` | Добавить конкретный файл. |
> | 2 | `git add <dir>/` | Добавить всё содержимое папки. |
> | 3 | `git add .` | Добавить все изменения в **текущей** директории и ниже. |
> | 4 | `git add -A` | Добавить в индекс всё, что изменилось в репозитории (all), включая удаления файлов. Т.е. **новые файлы** - добавит; **измененные** - обновит; **удаленные**, но ранее отслеживаемые - пометит на удаление.|

> [!EXAMPLE] ⚡ 2. Продвинутое добавление (Pro-level)
> Позволяет быть избирательным и не мусорить в истории.
>
> | № | Команда | Описание |
> | :-- | :--- | :--- |
> | 1 | `git add -p` | **Patch mode.** Интерактивный выбор конкретных кусков (hunks) кода внутри файлов. |
> | 2 | `git add -u` | Добавить только **изменения** уже отслеживаемых файлов (игнорирует новые файлы). |
> | 3 | `git add -n` | **Dry run.** Показать, какие файлы будут добавлены, но не добавлять их на самом деле. |

> [!DANGER] 🗑️ 3. Отмена добавления (Unstaging)
> Если ты случайно добавил лишнее в индекс.
>
> | № | Команда | Описание |
> | :-- | :--- | :--- |
> | 1 | `git restore --staged <file>` | Удалит файл из индекса, но оставит его в статусе **modified**|
> |*1.1*| `git restore --staged --source=HEAD <file>` | **Аналогично команде** `git restore --staged <file>`<br>**Через** `--source` можно явно указать источник: `--source=HEAD~3` , `--source=origin/main`
> |*1.2*| `git restore <file>` | Восстановит версию файла из WD и индекса до версии индекса или **HEAD** (если индекс не указан). Формально заменяет версию файла в WD и индексе на версию из индекса или HEAD **(без указания источника → по умолчанию индекс имеет приоритет)**. 
> | 2 | `git reset <file>` | Убрать файл из индекса (вернуть в **modified**), не удаляя правки. Старый аналог `git restore --staged <file>`|
> |3|`git rm --cached <file>`|Для удаления файла из репозитория, оставляя его на диске. Файл исключится из следующего коммита, даже если он добавлялся ранее. Файл станет **untracked**

### 💡 Внутренняя магия (Deep Dive)

Когда ты выполняешь `git add`, происходит три вещи:
1. Git берет содержимое файла и создает для него **Blob** (объект данных).
2. Вычисляется **SHA-1** хеш этого контента.
3. Git обновляет файл `.git/index`, связывая путь к файлу с новым хешем.

> [!TIP] Зачем нужен `-p` (Patch mode)?
> Это лучший способ делать **атомарные коммиты**. Если ты в одном файле `main.py` исправил баг и добавил новую функцию, `git add -p` позволит тебе разделить эти изменения на два разных коммита, предлагая выбрать каждый измененный блок отдельно.

> [!INFO] **Зачем это нужно?**
> 
> Ты целый час писал код в одном файле:
> 
> 1. Исправил баг в функции `A`.
>     
> 2. Добавил новую фичу в функции `B`.
>     
> 3. Оставил временный `print("!!!")` для отладки.
>     
> 
> С `-p` ты можешь сделать **два разных коммита** (баг и фичу) и **не добавлять** отладочный мусор.
#### Основные команды в режиме `-p`
Когда ты запустишь `git add -p`, под каждым куском кода появятся буквы `[y,n,q,a,d,s,e,?]`. Вот что они значат:

| **Команда** | **Клавиша** | **Описание**                                                                     |
| ----------- | ----------- | -------------------------------------------------------------------------------- |
| **Yes**     | `y`         | Добавить этот кусок в индекс.                                                    |
| **No**      | `n`         | Не добавлять этот кусок.                                                         |
| **Split**   | `s`         | Разбить текущий кусок на более мелкие (если Git видит между ними пустые строки). |
| **Quit**    | `q`         | Выйти и сохранить то, что уже успел выбрать.                                     |
| **All**     | `a`         | Добавить этот и все остальные куски в этом файле.                                |
| **Don't**   | `d`         | Пропустить этот и все остальные куски в этом файле.                              |
| **Edit**    | `e`         | Открыть этот кусок в редакторе и вручную удалить ненужные строки.                |
