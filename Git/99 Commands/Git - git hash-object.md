# 🛠️ git hash-object

> [!ABSTRACT] Суть
> Эта команда — фундамент системы хранения Git. Она берет любой поток данных и превращает его в уникальный 40-символьный идентификатор (хеш SHA-1). Это «входной билет» для контента, прежде чем он станет частью дерева или коммита.

>[!abstract] Синтаксис
>```bash
git hash-object [-t <тип>] [-w] [--stdin] [--no-filters] <файл>
>```

---
## 🚩 2. Основные флаги (Key Flags)

> [!SETTINGS] Основные флаги `git hash-object` 🚩
> 
> | **Флаг** | **Mnemonic** | **Подробное описание** | **Пример использования** |
> | :--- | :--- | :--- | :--- |
> | `-w` | **W**rite | **Запись в БД.** Гит не просто считает хеш, а сжимает данные и сохраняет их в директорию `.git/objects/`. | `git hash-object -w main.py` |
> | `--stdin` | **St**andard **In**put | **Ввод через поток.** Позволяет хешировать текст напрямую из консоли через pipe (конвейер). | `echo "test" \| git hash-object --stdin` |
> | `-t <тип>` | **T**ype | **Тип объекта.** По умолчанию это `blob` (файл), но можно создать `tree` (папка) или `commit`. | `git hash-object -t blob file.txt` |
> | `--no-filters` | **No** Filters | **Без обработки.** Игнорирует настройки `.gitattributes` (например, не меняет CRLF на LF), хешируя файл "как есть". | `git hash-object --no-filters file.bin` |
> | `--path` | Path | **Путь.** Помогает Git определить, какие фильтры применить к данным, если они читаются не из файла. | `echo "..." \| git hash-object --path=src/app.js` |

## 👨‍🍳 3. Полезные рецепты (Cookbook)

> [!EXAMPLE] Вычисление хеша существующего файла
> 
> Удобно для проверки целостности или сравнения файлов без их изменения в репозитории.
> 
> Bash
> 
> ```
> git hash-object file.txt
> ```

> [!TIP] Хеширование строки "на лету"
> 
> Используй этот метод, чтобы понять, как Git идентифицирует конкретные сообщения или фрагменты кода.
> 
> Bash
> 
> ```
> echo -n "Hello, Git!" | git hash-object --stdin
> ```
> 
> _Примечание: Флаг `-n` у `echo` убирает символ новой строки, чтобы хеш был чистым._

> [!IMPORTANT] Ручная запись объекта в базу
> 
> Если тебе нужно принудительно добавить контент в `.git/objects`, минуя индекс (Staging Area).
> 
> Bash
> 
> ```
> git hash-object -w myfile.txt
> ```

> [!GEAR] ⚙️ 4. Under the Hood (Внутреннее устройство)
> 
> Git вычисляет хеш не только от содержимого файла. Перед данными он добавляет **технический заголовок**, который делает хеш уникальным для системы:
> 
> 1. **Формирование заголовка** 🏷️: Git берет тип объекта и его размер, разделяя их пробелом, и добавляет в конце нулевой байт (`\0`).
> 2. **Склеивание** 🧩: Заголовок прикрепляется к началу исходных данных.
> 3. **Хеширование** 🧮: SHA-1 вычисляется от всей полученной связки.
> 4. **Сжатие** 📦: Полученный объект сжимается алгоритмом **Zlib** перед записью на диск (если указан флаг `-w`).
> ### Математическая модель хеша:
> $${GitHash} = \text{SHA-1}({type} + \text{" "} + {size} + \text{"\\0"} + {content})$$
