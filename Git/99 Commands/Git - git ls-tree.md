# 🌳 git ls-tree

> [!ABSTRACT] Суть
> - Позволяет просматривать содержимое объектов tree, представляющих каталоги в репозитории. Она показывает файлы и каталоги на конкретный момент истории коммитов, что полезно для разработчиков, которые нужно ориентироваться в состоянии проекта на разных этапах его разработки.

### 🛠 Синтаксис

```bash
git ls-tree <tree-ish> [path]
```

- **`<tree-ish>`**: Это может быть имя ветки (`main`), тег или хэш коммита. Чаще всего используют `HEAD` (текущий коммит).
- **`[path]`**: Необязательно. Если хочешь посмотреть содержимое конкретной папки.

---
### 🔍 Что ты увидишь в выводе?

Допустим, ты ввел `git ls-tree HEAD`. Типичный вывод выглядит так:

```plaintext
100644 blob e69de29bb2d1d6434b8b29ae775ad8c2e48c5391    README.md
040000 tree 3c34a2d398f64585f9e83897f22f7c0410090886    src
160000 commit a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0  vendor/lib
```

#### Разбор по столбцам:

|**Поле**|**Значение**|**Что это значит?**|
|---|---|---|
|**Mode**|`100644`, `040000`, `160000`|Права доступа и тип объекта (см. ниже).|
|**Type**|`blob`, `tree`, `commit`|`blob` — файл, `tree` — папка, `commit` — **сабмодуль**.|
|**Object SHA**|Хэш (40 символов)|Ссылка на содержимое объекта в базе `.git/objects`.|
|**File**|Имя файла/папки|Путь к объекту.|

---
### 💡 Самое важное: Магия режимов (Modes)

Для DevOps-инженера эти цифры — ключ к пониманию того, что Гит думает о твоих файлах:

- **`100644`**: Обычный текстовый файл.
    
- **`100755`**: **Исполняемый** файл (скрипт). Гит помнит, что у него стоит флаг `+x`. Если твой Bash-скрипт в репозитории имеет режим `100644` — в CI/CD он не запустится.
    
- **`040000`**: Директория (вложенное дерево).
    
- **`160000`**: **Тот самый сабмодуль!** Гит видит его как «gitlink». Обрати внимание: тип объекта для него указан как `commit`, а не `tree`.

---

### ❓ Когда тебе это пригодится в жизни?

1. **Проверка сабмодулей:** Быстро узнать, на какой именно хэш настроен сабмодуль в конкретной ветке, не заходя в папку.
    
2. **Отладка прав доступа:** Если пайплайн падает с ошибкой «Permission denied», ты пишешь `ls-tree` и видишь, что у скрипта стоит `100644` вместо `100755`.
    
3. **Поиск «призраков»:** Иногда файл удален с диска, но Гит почему-то всё еще считает, что он есть в индексе. `ls-tree` покажет правду.

---

### 🎙️ На собеседовании (например, в Aston):

> «Я использую `git ls-tree` для инспекции объектов внутри дерева коммитов. Это позволяет мне видеть метаданные файлов, такие как режим доступа (например, 100755 для скриптов) и хэши объектов. Также это основной способ проверить состояние **gitlinks** (режим 160000) для сабмодулей, чтобы убедиться, что основной репозиторий ссылается на правильный коммит внешней библиотеки».
