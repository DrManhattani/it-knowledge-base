# 🏗️ git worktree

> [!ABSTRACT] **Определение**
> 
> `git worktree` — это инструмент, позволяющий прикрепить несколько рабочих директорий к одному локальному репозиторию. Каждая такая директория связана с одной конкретной веткой, что позволяет работать над разными задачами параллельно, не используя `stash` и не делая `checkout`.
> 
> **Полезен когда:**
> - работа над несколькими ветками одновременнно
> - разработка фитч, требующая частого переключения веток
> - исправление багов без необходимости коммитить недописанный код
> - уменьшение необходимости stash и checkout

---
### ⚖️ Сравнение: Worktree vs. Stash

|**Характеристика**|**git stash**|**git worktree**|
|---|---|---|
|**Суть**|«Прячет» код в стек.|Создает физическую папку на диске.|
|**Переключение**|Нужно очистить WD, чтобы сменить ветку.|Просто переходишь в другое окно IDE / папку.|
|**Тесты**|Нельзя запустить тесты на двух ветках сразу.|**Можно.** Каждая папка независима.|
|**Сложность**|Легко запутаться в `stash@{n}`.|Всё наглядно в файловой системе.|

### 🛠️ Командный интерфейс

| **Команда** | **Описание**                                    | **Пример**                                 |
| ----------- | ----------------------------------------------- | ------------------------------------------ |
| `add`       | Создать новую папку и привязать к ней ветку.    | `git worktree add ../fix-task feature/fix` |
| `list`      | Показать все активные рабочие области.          | `git worktree list`                        |
| `remove`    | Удалить рабочую область (папку). Но не ветку!   | `git worktree remove ../fix-task`          |
| `prune`     | Очистить метаданные о вручную удаленных папках. | `git worktree prune`                       |

### 🏗️ Архитектура синтаксиса `git worktree`

Главная команда, с которой все работают — это `add`. У неё самый гибкий и одновременно запутанный синтаксис.

#### 1. Добавление новой рабочей области (`add`)

##### 💠 Полная форма (Explicit)
```bash
git worktree add -b <new-branch> <path> <start-point>
```

**Что здесь происходит:**

- `-b <new-branch>`: Явное указание создать новую ветку.
    
- `<path>`: Путь к новой директории (может быть абсолютным или относительным).
    
- `<start-point>`: Конкретный коммит, тег или ветка, от которой нужно отпочковать новую ветку.

##### 💠 Сокращенная форма №1: Использование существующей ветки
```bash
git worktree add <path> <existing-branch>
```

- **Что опущено:** Флаг `-b`.
    
- **Почему:** Если вы указываете путь и название существующей ветки, Гит понимает, что создавать новую не нужно. Он просто «развернет» указанную ветку в указанной папке.

##### 💠 Сокращенная форма №2: «Ленивый» режим (Magic)
```bash
git worktree add <path>
```

- **Что опущено:** И название ветки, и точка старта.
    
- **Логика Гита:**
	1. Гит берет последнее слово из пути `<path>` в качестве названия ветки. Если вы пишете `git worktree add ../my-fix`, Гит будет искать ветку `my-fix`.
    
    2. Если такая ветка **существует**, он её использует.
    
    3. Если такой ветки **нет**, он создаст её от текущего `HEAD`.
    
- **Зачем это:** Это самый быстрый способ создать ветку и папку под одну задачу одной командой.

---
#### 2. Управление списком и очистка

Здесь синтаксис проще, так как он направлен на обслуживание уже созданных связей.

##### 💠 Просмотр состояний
```bash
git worktree list [--porcelain]
```

- **Полная форма:** С флагом `--porcelain` выводит данные в формате, удобном для скриптов (путь, хеш коммита, ветка — всё на отдельных строках).
    
- **Сокращение:** `git worktree list` (обычная таблица для глаз человека).

##### 💠 Удаление worktree
```bash
git worktree remove [-f] <worktree-name_or_path>
```

- **Полная форма:** С флагом `-f` (force). Нужен, если в той папке есть незакоммиченные изменения. Гит защищает вас от случайного удаления работы, поэтому без `-f` «грязную» папку он не удалит.
    
- **Сокращение:** `git worktree remove <path>`.

#### 💠 Глубокая очистка метаданных
```bash
git worktree prune
```

- **Почему это важно:** Если вы удалили папку воркрти просто через `rm -rf` (в обход Гиту), Гит всё еще хранит «административную запись» в `.git/worktrees`. Эта команда проходит по списку и удаляет записи для путей, которые больше не существуют на диске.

---

### 🔍 Реализация «под капотом» (Implementation details)

Когда вы выполняете полную команду `git worktree add <path> <branch>`, Гит делает три вещи:

1. **В главной директории:** В папке `.git/worktrees/` создается каталог с названием, соответствующим папке воркрти. Внутри него лежат свои файлы `index`, `HEAD` и `ORIG_HEAD`.
2. **В целевой директории:** Создается папка `<path>`, а внутри неё — файл `.git`.
    - **Важно:** Это не папка, а обычный текстовый файл.
    - **Содержимое:** Внутри одна строка: `gitdir: /путь/к/основному/репо/.git/worktrees/название_воркрти`.
3. **Блокировка:** Ветка, которая открыта в воркрти, помечается в основном репозитории как «занятая». Вы не сможете сделать на неё `checkout` или `reset` в другом окне.

### ❓ Вопросы на собеседовании

> [!IMPORTANT] **Популярные вопросы для Senior-позиций**
> 
> **1. Можно ли в двух разных worktree открыть одну и ту же ветку?**
> 
> - **Ответ:** **Нет.** Git запрещает это, чтобы избежать повреждения индекса и истории. Если вы попытаетесь сделать `checkout` ветки, которая уже открыта в другом воркрти, Гит выдаст ошибку.
>     
> 
> ---
> 
> **2. Как** `git worktree` **помогает при Code Review?**
> 
> - **Ответ:** Вам не нужно прерывать свою работу и «сташить» изменения. Вы просто создаете временный воркрти для ветки коллеги, запускаете там проект, проверяете и удаляете папку. Ваша основная ветка остается нетронутой в соседнем окне.
>     
> 
> ---
> 
> **3. Что будет, если я удалю папку воркрти через** `rm -rf`**, а не через** `git worktree remove`**?**
> 
> - **Ответ:** Файлы исчезнут, но Гит всё еще будет считать, что ветка занята этим воркрти. Чтобы почистить внутренние ссылки, придется запустить `git worktree prune`.
>     
> 
> ---
> 
> **4. Как ведут себя хуки (Git Hooks) в воркрти?**
> 
> - **Ответ:** Они общие. Так как база `.git` одна, все хуки из основной папки будут срабатывать и во всех воркрти.
>
