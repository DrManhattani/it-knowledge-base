# 🛠️ git mktree

> [!ABSTRACT] Суть
> Если `git ls-tree` позволяет «развернуть» дерево и увидеть список файлов, то `git mktree` работает в обратную сторону. Она берет текстовый список с описанием файлов и папок и упаковывает их в полноценный объект `tree` в базе данных Git.

>[!abstract] Синтаксис
>```bash
>git mktree [--missing] [--batch] [-z]
>```

---

## 🚩 1. Основные флаги (Key Flags)

> [!SETTINGS] Основные флаги `git mktree` 🚩
> | **Флаг** | **Mnemonic** | **Подробное описание** | **Пример использования** |
> | :--- | :--- | :--- | :--- |
> | `--missing` | **Missing** | Позволяет создать дерево, даже если указанные в нем объекты (хеши) еще не существуют в базе. | `cat list.txt \| git mktree --missing` |
> | `--batch` | **Batch** | Позволяет передавать несколько деревьев подряд в одном потоке данных. | `cat trees.txt \| git mktree --batch` |
> | `-z` | **Zero** | Указывает, что входные данные разделены нулевым байтом (`\0`), что важно для имен файлов с пробелами. | `git mktree -z` |

---

## 📋 2. Формат входных данных

> [!INFO] Структура строки
> Чтобы `mktree` понял, как собрать дерево, он ожидает на вход строки формата:
> 
> `mode type sha1 path`
> 
> * **mode** 🔢: 6-значный код прав доступа (например, `100644` для файла, `040000` для папки).
> * **type** 📄: Тип объекта (`blob` или `tree`).
> * **sha1** 🔑: 40-символьный хеш объекта.
> * **path** 📂: Имя файла или папки.

---

## ⚙️ 3. Under the Hood & Object DB

> [!GEAR] Взаимодействие с базой данных 🔗
> 1.  **Валидация** ✅: По умолчанию команда проверяет наличие всех указанных хешей в `.git/objects`. Если объекта нет — дерево не будет создано (если не указан `--missing`).
> 2.  **Сборка** 🏗️: Git сортирует записи по имени и формирует бинарный контент объекта `tree`.
> 3.  **Хеширование** 🧮: SHA-1 вычисляется от заголовка и списка содержимого.
> 
> ### Формула записи дерева:
> $$\text{TreeHash} = \text{SHA-1}(\text{"tree "} + \text{size} + \text{"\\0"} + \text{binary\_entries})$$

## 👨‍🍳 4. Полезные рецепты (Cookbook)

> [!EXAMPLE] Клонирование структуры существующего дерева
> Можно взять структуру одного дерева и создать на её основе точно такое же (новый объект в базе).
> ```bash
> git ls-tree HEAD | git mktree
> ```

> [!TIP] Ручное создание папки в базе объектов
> Полезно в скриптах, когда нужно создать "виртуальную" директорию без реального создания папок на диске.
> ```bash
> printf "100644 blob <hash> file.txt\n" | git mktree
> ```

## 🧠 5. Deep Dive / Question

> [!QUESTION] 1. Зачем создавать дерево вручную?
> Обычно `git add` делает это за нас, обновляя индекс. `mktree` же нужен для «чистого» манипулирования базой объектов. Это позволяет, например, создать коммит, который вообще не касается файлов в вашей рабочей директории (Working Directory).

> [!QUESTION] 2. Пакетный режим и тонкости форматирования
> 
> ### 📦 Пакетный режим (`--batch`)
> Позволяет генерировать несколько объектов деревьев за один сеанс. Гит понимает, что началось описание нового дерева, когда встречает **пустую строку** (`\n\n`) между блоками данных.
> ```
> 100644 blob a1b2c3d4...    file1.txt
100644 blob e5f6g7h8...    file2.txt
(пустая строка здесь)
100644 blob i9j0k1l2...    file3.txt
040000 tree m3n4o5p6...    sub-folder
> ```
> 
> ### 📋 Правила оформления входных данных
> Для корректной сборки дерева Git требует строгого соблюдения структуры строки:
> 
> | Элемент | Разделитель | Особенности |
> | :--- | :--- | :--- |
> | **Mode, Type, SHA-1** | Пробел | Стандартные атрибуты объекта. |
> | **SHA-1 и Path** | **Табуляция** (`\t`) | Между хешем и именем файла **обязательно** должен быть таб. |
> | **Path (Имя файла)** | Перенос строки (`\n`) | В обычном режиме имена с пробелами нужно брать в кавычки (например, `"My File.txt"`). |
> 
> ### 🤐 Зачем нужен флаг `-z`?
> Флаг `-z` меняет стандартный разделитель строк на **нулевой байт** (`\0`). Это критично в двух случаях:
> 1. **Сложные имена**: Если в имени файла есть пробелы, кавычки или переносы строк, `-z` позволяет передать их «как есть», без кавычек и экранирования бэкслешем.
> 2. **Автоматизация**: Большинство системных инструментов лучше обрабатывают списки с нулевым разделителем, так как это исключает двусмысленность при чтении путей.

> [!QUESTION] 3. Что такое «обычный режим»?
> Это режим работы `mktree` по умолчанию (без флага `-z`). В этом режиме Git ожидает, что каждая запись о файле находится на новой строке. Разделителем между записями служит стандартный символ переноса строки (`\n`).
>
> ### 2. Пробелы и кавычки 🔍
> В `mktree` формат ввода очень строгий:
> * **Без кавычек**: Если путь простой (например, `file.txt`), кавычки не нужны.
> * **С кавычками**: Если в пути есть пробелы или спецсимволы (например, `my file.txt`), Git в обычном режиме ожидает, что имя будет обернуто в двойные кавычки: `"my file.txt"`.
>
> ### 3. Перенос строки в конце 🔚
> * **Конец записи**: Каждая строка в списке **должна** заканчиваться переносом строки. Это сигнал для Git: «описание этого файла закончилось, жду следующее».
> * **Конец файла**: Лишний пустой перенос строки в конце файла допустим, но в режиме `--batch` **две** пустые строки подряд завершают описание текущего дерева.
>
> | Ситуация | Нужны ли кавычки? | Нужен ли перенос строки? |
> | :--- | :--- | :--- |
> | `file.txt` | Нет | Да (в конце строки) |
> | `my file.txt` | **Да** (в обычном режиме) | Да (в конце строки) |
> | Режим `-z` | **Никогда** | Нет (заменяется на `\0`) |
