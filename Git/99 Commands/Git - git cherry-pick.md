# 🍒 git cherry-pick

> [!ABSTRACT] **Определение (Interview-ready)**
> > **git cherry-pick** — это операция **дифференциального переноса**, которая вычисляет разницу (patch) между выбранным коммитом и его непосредственным родителем в исходной ветке и применяет этот патч к текущему `HEAD`.
>
> **Критический нюанс:** Эта команда игнорирует всю предыдущую историю ветки (все коммиты, идущие до выбранного). Она не «втягивает» состояние проекта, а воспроизводит только те строки кода, которые были изменены именно в этом конкретном коммите.
---

> [!SETTINGS] **Синтаксис и структура**
>
> ### 📘 Формальное описание (POSIX/Man-style)
>
> ```text
> git cherry-pick [<options>] <commit-ish>...
> git cherry-pick --continue | --skip | --abort | --quit
> ```
> 
> ### 📋 Детальный разбор параметров
>
> | Элемент | Техническое описание | Роль в операции |
> | :--- | :--- | :--- |
> | `<commit-ish>...` | **Целевые коммиты** | Хеши коммитов или имена веток. Можно передать список через пробел или диапазон (напр. `A..B`). |
> | `--continue` | **Продолжение** | Выполняется после ручного разрешения конфликтов. |
> | `--abort` | **Отмена** | Возвращает ветку в состояние до начала операции. |

---
### 🚩 Ключевые флаги (Professional Options)

| Флаг   | Полное имя        | Техническое назначение                                                                                                                                             |
| :----- | :---------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-n`   | `--no-commit`     | **Stage only.** Применяет изменения в индекс и рабочую директорию, но не создает коммит автоматически. Полезно для объединения нескольких "вишенок" в один коммит. |
| `-x`   | —                 | **Traceability.** Добавляет в сообщение коммита строку `(cherry picked from commit ...)`. Критически важно для отслеживания происхождения патча.                   |
| `-m 1` | `--parent-number` | **Merge-pick.** Позволяет забрать изменения из merge-коммита, указывая, относительно какого родителя (обычно 1) вычислять диф.                                     |
| `-s`   | `--signoff`       | Добавляет подпись автора (Signed-off-by) в конец сообщения коммита.                                                                                                |

---
### 🏗️ Внутренняя логика (How it works)

1. **Diff Generation:** Git вычисляет разницу (diff) между выбранным коммитом и его непосредственным родителем.
2. **Patch Application:** Полученный патч накладывается на текущий `HEAD`.
3. **Commit Creation:** Создается новый объект коммита с тем же автором и сообщением (если не указано иное), но с **новым SHA-1 хешем** и текущим временем.
4. **Conflict Check:** Если изменения в патче пересекаются с текущим состоянием файлов — Git останавливается и просит разрешить конфликт.

---
### 🛠️ Практические сценарии

> [!EXAMPLE] **Hotfix: Перенос исправления в Stable**
> Ты нашел баг в `develop`, исправил его, и теперь это же исправление нужно срочно доставить в `master`, не вливая весь `develop`.
> ```bash
> git checkout master
> git cherry-pick <hash-of-fix-from-develop>
> ```

> [!EXAMPLE] **Воскрешение работы из удаленной ветки**
> Если ветка была неудачной, но один коммит в ней был гениальным:
> ```bash
> git cherry-pick <commit-hash>
> ```

> [!EXAMPLE] **Сборка нескольких коммитов в один (с** `-n`**)**
> ```bash
> git cherry-pick -n <hash1>
> git cherry-pick -n <hash2>
> # Теперь оба изменения в индексе, можно сделать один коммит
> git commit -m "Merged features from two separate commits"
> ```

---
### ⚠️ Риски и нюансы

* **Дублирование (Duplicate Commits):** Постоянное использование `cherry-pick` вместо `merge` приводит к тому, что в истории появляются одинаковые по смыслу, но разные по хешам коммиты. Это может запутать `git merge` в будущем.
* **Потеря контекста:** Коммит может не заработать в новой ветке, если он зависит от кода, который не был перенесен.
* **Конфликты:** Если целевой файл сильно отличается от того, на котором делался оригинальный коммит.
