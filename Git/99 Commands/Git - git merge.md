# 🧬 git merge

> [!ABSTRACT] **Определение (Interview-ready)**
> **git merge** — это команда, которая интегрирует изменения из указанной ветки в текущую, создавая новую точку в графе истории. На техническом уровне Git находит **общего предка** (base commit) двух веток и выполняет трехстороннее слияние (three-way merge) между текущим `HEAD`, целевой веткой и их базовым коммитом. Результатом может быть либо простое перемещение указателя ветки (Fast-forward), либо создание специального **коммита слияния** (merge commit), имеющего двух и более родителей.

---

> [!SETTINGS] **Синтаксис и структура**
>
> ### 📘 Формальное описание (POSIX/Man-style)
>
> ```text
> git merge [<options>] [<commit>...]
> git merge --abort
> git merge --continue
> ```
> 
> ### 📋 Детальный разбор параметров
>
> | Элемент | Техническое описание | Роль в операции |
> | :--- | :--- | :--- |
> | `[<options>]` | **Модификаторы стратегии** | Флаги, управляющие тем, как именно Git будет соединять ветки (например, `--squash` или `--no-ff`). |
> | `[<commit>...]` | **Цель слияния** | Обычно это имя ветки (напр. `feature`), которую вы хотите влить в текущую (HEAD). Можно указать несколько веток сразу (Octopus merge). |
> | `--abort` | Команда отката | Полный сброс процесса слияния при возникновении конфликтов. Возвращает состояние репозитория к точке `PRE_MERGE`. |

---

### 🚩 Ключевые флаги (Professional Options)

| Флаг        | Полное имя          | Техническое назначение                                                                                                                                                       |
| :---------- | :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--squash`  | `--squash`          | **Схлопывание.** Берет все изменения из вливаемой ветки и помещает их в индекс как один набор изменений. **Не создает** коммит слияния; требует ручного коммита.             |
| `--no-ff`   | `--no-fast-forward` | **Сохранение топологии.** Даже если возможно линейное смещение, Git создаст коммит слияния. Это важно для DevOps, чтобы видеть в графе, где начиналась и заканчивалась фича. |
| `--ff-only` | `--ff-only`         | **Защита.** Слияние произойдет только в том случае, если историю можно просто «перемотать» вперед. Если ветки разошлись — операция прервется.                                |
| `--abort`   | `--abort`           | Прекращает процесс слияния и пытается восстановить состояние до начала слияния.                                                                                              |

> [!NOTE] **Проверка перед слиянием**
> В Git нет флага `--diff` внутри команды `merge`. Чтобы посмотреть изменения перед слиянием, используется:
> `git diff <текущая_ветка>..<вливаемая_ветка>`

### 🏷️ Разбор вывода (Output Analysis)

#### 📋 Общий пример вывода (3-way merge)
```text
Auto-merging index.md
Merge made by the 'recursive' strategy.
 index.md | 5 ++++-
 1 file changed, 4 insertions(+), 1 deletion(-)
```

#### 🔍 Частный разбор состояний (Statuses)

|**Статус**|**Пример строки**|**Техническая интерпретация**|
|---|---|---|
|**Fast-forward**|`Updating a1b2c3d..e5f6g7h Fast-forward`|Линейное обновление. Общий предок совпадает с текущим HEAD.|
|**Recursive**|`Merge made by the 'recursive' strategy.`|Стандартное слияние с поиском общего предка. Создан merge-commit.|
|**Conflict**|`CONFLICT (content): Merge conflict in file.js`|**Требуется вмешательство.** Git не смог автоматически объединить изменения в одних и тех же строках.|
|**Squash**|`Squash commit -- not updating HEAD`|Изменения перенесены в индекс, но история вливаемой ветки не задействована.|

### 🏗️ Внутренняя логика (How it works)

1. **Finding Ancestor:** Git ищет **LCA** (Lowest Common Ancestor) — последнего общего родителя обеих веток.
2. **Analysis:**
    - Если HEAD совпадает с LCA — происходит **Fast-forward**.
    - Если ветки разошлись — запускается алгоритм **Three-way merge**.
3. **Execution:** Git сравнивает LCA, текущий HEAD и вливаемую ветку. Если изменения не пересекаются в одних строках — создается коммит.
4. **Metadata:** В файле `.git/MERGE_HEAD` временно хранится хеш вливаемого коммита до завершения операции.

### 🛠️ Сценарии использования (Best Practices)

> [!EXAMPLE] **Чистая история в Main (Squash)**
> 
> Чтобы не засорять основную ветку мелкими коммитами из feature-ветки (особенно актуально для ML-экспериментов):
> 
> 
> ```bash
> git checkout main
> git merge --squash feature-experiment
> git commit -m "Add complete feature-experiment"
> ```

> [!EXAMPLE] **Безопасное вливание (DevOps Flow)**
> 
> Гарантируем, что мы не создаем лишних узлов, если история линейна:
> 
> ```bash
> git merge --ff-only feature-fix
> ```

> [!EXAMPLE] **Отмена при конфликтах**
> 
> Если при слиянии всё пошло не так и файлов слишком много:
> 
> ```bash
> git merge --abort
> ```
