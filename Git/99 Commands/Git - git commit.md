# 📸 git commit

> [!ABSTRACT] Суть
> Команда берет текущее состояние **Индекса** и сохраняет его как новый объект в истории. Каждый коммит содержит ссылку на дерево файлов, автора, дату и хеш «родителя», что и образует цепочку (ветку).

---

> [!INFO] 🔍 1. Базовое создание (Standard)
> Эти команды — твой «хлеб насущном» при ежедневной разработке.
>
> | № | Команда | Описание |
> | :-- | :--- | :--- |
> | 1 | `git commit -m "msg"` | Создать коммит с коротким сообщением. |
> | 2 | `git commit -a -m "msg"` | **Skip Add.** Добавляет все измененные/удаленные файлы и коммитит (игнорирует новые файлы!). |
> | 3 | `git commit -v` | **Verbose.** Открывает редактор и показывает `diff` изменений прямо под местом для сообщения. |

> [!WARNING] 🛠️ 2. Исправление и модификация
> Будь осторожен: эти команды меняют историю (хеш коммита изменится).
>
> | № | Команда | Описание |
> | :-- | :--- | :--- |
> | 1 | `git commit --amend` | Добавить забытые файлы или изменить сообщение последнего коммита. |
> | 2 | `git commit --amend --no-edit` | Обновить последний коммит новыми файлами, не меняя его текст. |

> [!SETTINGS] ⚙️ 3. Специфические флаги
> | № | Флаг | Описание |
> | :-- | :--- | :--- |
> | 1 | `--allow-empty` | Создать коммит, даже если в Индексе нет изменений (полезно для триггеров CI/CD). |
> | 2 | `-s` (`--signoff`) | Добавить строку `Signed-off-by: Name <email>` (подтверждение авторства по DCO). |
> | 3 | `--date="date"` | Указать произвольную дату совершения коммита. |

---
### 💡 Глубокая логика (по документации)

#### Механика `-a` (All)
Важнейший нюанс: флаг `-a` автоматически делает `add` только для тех файлов, о которых Git **уже знает** (статусы Modified и Deleted). Если ты создал новый файл (Untracked), флаг `-a` его **не подберет**. Тебе всё равно придется сделать `git add` вручную.
#### Что такое `--amend` на самом деле?
Когда ты делаешь «аменд», Git не «редактирует» старый коммит. Он:
1. Создает **совершенно новый** объект коммита.
2. Подменяет им старый в текущей ветке.
3. Старый коммит со временем удаляется сборщиком мусора.
*Никогда не делай `amend` для коммитов, которые ты уже отправил (push) в общий репозиторий!*

---
### 📝 Требования к хорошему коммиту
1. **Атомарность**: Один коммит = одна задача/исправление.
2. **Заголовок**: До 50 символов, в повелительном наклонении (напр., *"Fix bug"* вместо *"Fixed bug"*).
3. **Тело**: Если нужно описание, отдели его от заголовка пустой строкой.
