# 🌿 git branch

> [!ABSTRACT] Суть
> Ветка в Git — это просто перемещаемый указатель на коммит. Команда `git branch` управляет этими указателями, но **не** переключает тебя между ними (для этого нужен `switch` или `checkout`).

---

> [!INFO] 🔍 1. Просмотр и навигация
> | № | Команда | Описание |
> | :-- | :--- | :--- |
> | 1 | `git branch` | Список локальных веток. Текущая отмечена `*`. |
> | 2 | `git branch -a` | **All.** Показать локальные и удаленные (`remotes/`) ветки. |
> | 3 | `git branch -r` | **Remote.** Показать только ветки на удаленном сервере. |
> | 4 | `git branch -vv` | **Very Verbose.** Показать последний коммит и связь с удаленной веткой (ahead/behind). |

> [!EXAMPLE] 🛠️ 2. Создание и изменение
> | № | Команда | Описание |
> | :-- | :--- | :--- |
> | 1 | `git branch <name>` | Создать новую ветку от текущего места. |
> | 2 | `git branch -m <old> <new>` | Переименовать ветку `<old>` в `<new>`. |
> | 3 | `git branch -m <new>` | Переименовать **текущую** ветку. |

> [!DANGER] 🗑️ 3. Удаление (Cleanup)
> | № | Команда | Описание | Риск |
> | :-- | :--- | :--- | :--- |
> | 1 | `git branch -d <name>` | **Safe delete.** Удалит ветку, только если она уже слита (merged).<br>**Проверяет**, слит ли код в другие ветки или отправлен ли он в **upstream** (на сервер).<br>**Если код уникален** — удаление блокируется.| ✅ Безопасно |
> | 2 | `git branch -D <name>` | **Force delete.** Принудительное удаление. Удаляет ветку, даже если в ней остались уникальные коммиты, которые вы больше нигде не увидите. | 🔥 Опасно |

---
### 💡 Глубокая логика (по документации)

#### Почему `-d` — это предохранитель?
Git проверяет состояние указателя. Если коммиты в ветке, которую ты хочешь удалить, не достижимы из текущей ветки (чтобы удалить ветку, нужно находиться в любой другой ветке, кроме удаляемой) или её `upstream`, Git выдаст ошибку. Это защита от случайной потери работы, которую ты еще не успел «спасти» в основной ветке.
#### Что на самом деле делает `-vv`?
Этот флаг лезет в твой конфиг (`.git/config`) и сравнивает локальный хеш с хешем, который был подтянут с сервера при последнем `git fetch`.
* Если видишь `[ahead 2]`, значит у тебя 2 коммита, которых еще нет на сервере.
* Если `[behind 5]`, значит на сервере появились 5 новых коммитов, которые пора стянуть.

# 🔗 git branch --set-upstream-to

> [!ABSTRACT] **Определение (Interview-ready)**
> **--set-upstream-to** (короткий флаг **-u**) — это опция команды `git branch`, которая устанавливает связь «отслеживания» (tracking relationship) между локальной веткой и веткой в удаленном репозитории (remote-tracking branch). Это позволяет Git сопоставлять их истории и активирует механизм автоматического определения цели для команд `git pull`, `git push` и расширенного вывода в `git status`.

---

> [!SETTINGS] **Синтаксис и структура**
>
> ### 📘 Формальное описание
>
> ```text
> git branch [--set-upstream-to=<upstream> | -u <upstream>] [<branchname>]
> ```
> 
> ### 📋 Разбор параметров
>
> | Элемент | Техническое описание |
> | :--- | :--- |
> | `<upstream>` | Полное имя удаленной ветки в формате `<remote>/<branch>` (напр. `origin/main`). |
> | `[<branchname>]` | Имя локальной ветки, которую нужно связать. Если не указано — связывается текущая ветка (HEAD). |

---
### 🏗️ Внутренняя логика (How it works)

Когда ты выполняешь эту команду, Git не идет в интернет. Он просто записывает две строчки в твой локальный файл `.git/config`:

1. **`remote`**: Имя сервера (напр. `origin`).
2. **`merge`**: Ссылку на ветку на этом сервере (напр. `refs/heads/main`).

> [!INFO] **Что это дает на практике?**
> - **Умный статус:** `git status` начнет писать: *"Your branch is ahead of 'origin/main' by 2 commits"*.
> - **Короткие команды:** Ты сможешь писать просто `git pull` вместо `git pull origin main`.
> - **Сравнение:** Гит сможет автоматически вычислять разницу между локальным и удаленным состоянием.

---
### 📊 Сравнение с `git push -u`

| Характеристика          | `git push -u origin main`            | `git branch -u origin/main`                                                      |
| :---------------------- | :----------------------------------- | :------------------------------------------------------------------------------- |
| **Когда использовать?** | При первой отправке ветки на сервер. | Когда ветка уже есть и там, и там, но связь не установлена или её нужно сменить. |
| **Действие**            | Отправляет данные + ставит связь.    | **Только** ставит связь (метаданные).                                            |
| **Требует сеть?**       | Да, обязательно.                     | Нет, работает только с локальным конфигом.                                       |

---
### 🛠️ Практические сценарии

> [!EXAMPLE] **Кейс 1: Связь после ручного создания**
> Ты создал ветку `dev` локально, а твой коллега создал `dev` на сервере. Чтобы Git их «подружил»:
> ```bash
> git branch --set-upstream-to=origin/dev dev
> ```

> [!EXAMPLE] **Кейс 2: Переезд на новую ветку**
> Ты работал с `origin/feature-old`, но на сервере её переименовали в `origin/feature-new`. Чтобы перенаправить свою локальную ветку:
> ```bash
> git branch -u origin/feature-new
> ```

> [!EXAMPLE] **Кейс 3: Проверка связей**
> Чтобы увидеть, какая ветка куда "смотрит" прямо сейчас:
> ```bash
> git branch -vv
> ```
