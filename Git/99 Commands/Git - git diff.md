# 🔍 git diff: Искусство сравнения

> [!ABSTRACT] Суть
> Сравнивает изменения между различными состояниями файлов в репозитории. Показывает разницу между файлами в рабочей директории, индексом или последним коммитом.

---
### 🗺️ 1. Сравнение между зонами (The Golden Triangle)

Это самая важная часть. Чтобы не запутаться, представь три точки: **Рабочая директория (WD)**, **Индекс (Staging)** и **Последний коммит (HEAD)**.

| Команда             | Что с чем сравнивает? | Сценарий использования                                             |
| :------------------ | :-------------------- | :----------------------------------------------------------------- |
| `git diff`          | **WD ↔ Index**        | «Что я написал после последнего `git add`?»                        |
| `git diff --staged` | **Index ↔ HEAD**      | «Что именно попадет в коммит, если я нажму commit прямо сейчас?»   |
| `git diff HEAD`     | **WD ↔ HEAD**         | «Все изменения с момента последнего коммита (и в индексе, и нет).» |

---
### 🧬 2. Анатомия вывода (Как это читать?)

Когда ты запускаешь `git diff`, Гит выдает текст в формате **Unified Diff**. Разберем его на примере:

```
diff --git a/notes.md b/notes.md
index 1a2b3c4..5d6e7f8 100644
--- a/notes.md
+++ b/notes.md
@@ -1,4 +1,5 @@
 Привет!
-Это старая строка.
+Это новая строка, которую я добавил.
+И еще одна.
 Конец файла.
```
> [!INFO] **Разбор символов:**
> 
> 1. `--- a/notes.md` / `+++ b/notes.md`: Старая версия (a) и новая версия (b).
>     
> 2. `-` (минус): Строка была удалена или изменена.
>     
> 3. `+` (плюс): Строка была добавлена.
>     
> 4. `@@ -1,4 +1,5 @@` (Чанк/Chunk)**:
>     
>     - `-1,4`: В старом файле Гит показывает кусок, начиная с **1-й** строки, длиной **4** строки.
>         
>     - `+1,5`: В новом файле этот же кусок начинается с **1-й** строки, но теперь он длиной **5** строк.
>         

>[!INFO] 🕵️ Технический нюанс по `@@ -X,Y +A,B @@`
Если ты видишь `@@ -45,7 +45,12 @@`, это значит:
> - В оригинале мы смотрим на блок с 45-й строки, который занимал 7 строк.
> - Теперь на этом месте блок, который также начинается с 45-й строки, но занимает 12 строк (значит, ты добавил 5 строк внутри этого блока).

### 🛠️ 3. Продвинутые фильтры и опции

Иногда изменений так много, что лог становится нечитаемым. Здесь помогают флаги:

> [!EXAMPLE] **Примеры точечного поиска**
> 
> 1. **Игнорировать пробелы** (`-w`):
>     
>     `git diff -w`
>     
>     _Если ты просто переставил табуляцию или пробелы, Гит проигнорирует это и покажет только изменения в буквах._
>     
> 2. **Только конкретный файл**:
>     
>     `git diff HEAD notes.md`
>     
> 1. **Фильтр по типу действия** (`--diff-filter`):
>     
>     - `git diff --diff-filter=A` (покажет только файлы, которые были **созданы**).
>         
>     - `git diff --diff-filter=D` (покажет только **удаленные** файлы).
>         
> 2. **Статистика вместо кода** (`--stat`):
>     
>     `git diff --stat`
>     
>     _Покажет только список файлов и количество измененных строк (как в `git commit`)._
>     

---

### 🕰️ 4. Сравнение коммитов и веток

Ты можешь сравнивать любые точки в истории, а не только текущие файлы.

|**Команда**|**Описание**|
|---|---|
|`git diff 1a2b3c 4d5e6f`|Сравнить два конкретных коммита по их хешам.|
|`git diff main feature`|Показать разницу между кончиками двух веток.|
|`git diff HEAD~3 HEAD`|Показать всё, что изменилось за последние 3 коммита.|

### 💡 Профессиональные советы для Obsidian

1. **`git diff --word-diff`**: Показывает изменения внутри строки (вместо того чтобы удалять всю строку и писать новую, он выделит измененные слова в скобки `[-удалено-]{+добавлено+}`). **Очень удобно для текстов и заметок!**
2. **Сравнение с сервером**:
    `git fetch origin`
    `git diff main origin/main`
    _Это покажет тебе, что именно изменилось на сервере по сравнению с твоим локальным кодом, прежде чем ты сделаешь `merge`._
