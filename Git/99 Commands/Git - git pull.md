# 📥 git pull

> [!ABSTRACT] **Определение (Interview-ready)**
> **git pull** — это высокоуровневая команда синхронизации, объединяющая в себе последовательный вызов `git fetch` и `git merge` (или `git rebase`). Она предназначена для извлечения изменений из удаленного репозитория и их немедленной интеграции в текущую активную ветку. Это "агрессивная" команда, так как она напрямую модифицирует рабочую директорию и историю коммитов.

---

> [!SETTINGS] **Синтаксис и структура**
>
> ### 📘 Формальное описание (POSIX/Man-style)
>
> ```text
> git pull [<options>] [<repository> [<refspec>...]]
> ```
> 
> ### 📋 Детальный разбор параметров
>
> | Элемент | Техническое описание | Роль в операции |
> | :--- | :--- | :--- |
> | `[<options>]` | **Модификаторы интеграции** | Флаги, определяющие способ слияния. Например, `--rebase` (линейная история), `--ff-only` (безопасный апдейт) или `--autostash`. |
> | `[<repository>]` | **Целевой сервер** | Алиас удаленного репозитория (напр. `origin`). Если не указан, Git использует `upstream`, настроенный для текущей ветки. |
> | `[<refspec>...]` | **Спецификация ссылок** | Указывает, какую именно ветку сервера нужно затянуть в текущую (напр. `main`). |

---
### 🚩 Ключевые флаги (Professional Options)

| Флаг          | Полное имя    | Техническое назначение                                                                                                                  |
| :------------ | :------------ | :-------------------------------------------------------------------------------------------------------------------------------------- |
| `-r`          | `--rebase`    | Вместо `merge` использует `rebase`. Исключает создание лишних merge-коммитов, сохраняя историю линейной.                                |
| `--ff-only`   | `--ff-only`   | **Safety Mode.** Позволяет обновиться только в режиме Fast-forward. Если история разошлась — команда прервется, не создавая конфликтов. |
| `-v`          | `--verbose`   | **Logging.** Подробный вывод стадий fetch и стратегии объединения объектов.                                                             |
| `--autostash` | `--autostash` | Автоматически прячет ваши грязные изменения (`stash`) перед началом pull и возвращает их после завершения.                              |

### 🏗️ Внутренняя логика (Execution Workflow)

1. **Phase 1: Fetch.** Выполняется `git fetch`, скачиваются объекты в `.git/objects` и обновляется `refs/remotes/`.
2. **Phase 2: Discovery.** Git определяет, какая ветка является `upstream` для текущей, и находит `FETCH_HEAD`.
3. **Phase 3: Integration.** В зависимости от флагов выполняется либо `git merge FETCH_HEAD`, либо `git rebase FETCH_HEAD`.

### 🛠️ Сценарии использования (Best Practices)

> [!EXAMPLE] **Профессиональный стандарт обновления (Clean History)**
> 
> Избегаем захламления истории лишними merge-коммитами:
> 
> 
> ```bash
> git pull --rebase origin main
> ```

> [!EXAMPLE] **Безопасное обновление без риска конфликтов**
> 
> Обновиться только если это не требует слияния историй:
> 
> 
> ```bash
> git pull --ff-only
> ```
