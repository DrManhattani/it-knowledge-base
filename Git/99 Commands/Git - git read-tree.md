# 🛠️ git read-tree

> [!ABSTRACT] Суть
> Если `mktree` создает объект дерева из текста, то `read-tree` делает обратное: берет существующий хеш дерева из базы объектов и «раскладывает» его в твой индекс. Это фундаментальная часть механики `git checkout` и `git merge`.

>[!abstract] Синтаксис
>```bash
>git read-tree [[-m [--trivial] [--aggressive] | --reset | --prefix=<prefix>] [-u | -i]] <tree-ish>
>```

---
## 🚩 1. Основные флаги (Key Flags)

> [!SETTINGS] Основные флаги `git read-tree` 🚩
> 
> | **Флаг** | **Mnemonic** | **Подробное описание** | **Пример использования** |
> | :--- | :--- | :--- | :--- |
> | `-m` | **M**erge | **Слияние.** Пытается объединить два или более деревьев. Если возникают конфликты, они помечаются в индексе специальными стадиями (1, 2, 3). | `git read-tree -m tree1 tree2` |
> | `-u` | **U**pdate | **Обновление WD.** Не просто меняет индекс, но и физически обновляет файлы в твоей рабочей директории, чтобы они соответствовали дереву. | `git read-tree -u <hash>` |
> | `--reset` | **Reset** | **Сброс.** Полностью очищает текущий индекс и заменяет его содержимое указанным деревом. Игнорирует незакоммиченные изменения. | `git read-tree --reset HEAD` |

---
## 👨‍🍳 2. Полезные рецепты (Cookbook)

> [!EXAMPLE] Быстрое переключение индекса на другой коммит
> Если нужно подготовить индекс к состоянию старого коммита, не меняя ветку.
> ```bash
> git read-tree --reset <hash_старого_коммита>
> ```

> [!IMPORTANT] Синхронизация индекса и диска
> Обычно `read-tree` меняет только индекс. Чтобы изменения отразились на файлах, всегда добавляй `-u`.
> ```bash
> git read-tree -u --reset HEAD
> ```

---
## ⚙️ 3. Under the Hood (Внутреннее устройство)

> [!GEAR] Как Git «читает» дерево 🌳
> 
> Команда работает как транслятор между бинарным объектом `tree` и бинарным файлом `.git/index`:
> 
> 1. **Парсинг** 🔍: Git считывает объект дерева по хешу.
> 2. **Рекурсия** 🔄: Если внутри дерева есть другие деревья (папки), Git заходит в них и извлекает все вложенные блобы.
> 3. **Маппинг** 🗺️: Для каждого найденного файла создается запись в индексе.
> 
> ### Логика заполнения индекса:
> $$IndexEntry = \{Path, Mode, SHA-1(Blob), Stage\}$$
> 
> При использовании `-m` Git сравнивает записи из нескольких деревьев и выставляет `Stage > 0`, если данные по одному и тому же пути различаются.

## 🧠 4. Deep Dive / Question

> [!QUESTION] В чем разница между `git read-tree --reset HEAD` и `git reset --hard HEAD`?
> 
> Хотя названия похожи, работают они на разных уровнях:
> 1. `git reset --hard` — это **высокоуровневая (porcelain)** команда. Она передвигает указатель ветки, обновляет индекс и рабочую директорию.
> 2. `git read-tree --reset` — это **низкоуровневая (plumbing)** команда. Она **не двигает ветку**. Она просто берет состояние дерева и «впечатывает» его в индекс (и в WD, если указан `-u`). 
> 
> Это позволяет тебе «примерить» состояние любого дерева на свой индекс, не меняя того, на каком коммите ты сейчас официально находишься.
