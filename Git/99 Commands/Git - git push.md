# 📤 git push

> [!ABSTRACT] **Определение (Interview-ready)**
> **git push** — это команда публикации, предназначенная для передачи локальных объектов (commits, blobs, trees) в удаленный репозиторий и обновления его указателей (refs). Она устанавливает соответствие между локальной историей и состоянием сервера. В отличие от `fetch`, `push` требует прав на запись и может быть отклонен сервером, если удаленная ветка ушла вперед (non-fast-forward error).
>> [!warning] Особенности:
>> - Git отправляет **только текущую ветку**, а не все локальные ветки. Потому что используется правило **push.default**.
> 

---

> [!SETTINGS] **Синтаксис и структура**
>
> ### 📘 Формальное описание (POSIX/Man-style)
>
> ```text
> git push [<options>] [<repository> [<refspec>...]]
> git push <remote> <src>:<dst>
> ```
> 
> ### 📋 Детальный разбор параметров
>
> | Элемент | Техническое описание | Роль в операции |
> | :--- | :--- | :--- |
> | `[<options>]` | **Флаги модификации** | Управляют поведением отправки: форсирование, удаление, установка связей или работа с тегами. |
> | `[<repository>]` | **Целевой сервер** | Удаленный репозиторий (алиас, например `origin`). Если не указан, используется `upstream` текущей ветки. |
> | `[<refspec>...]` | **Спецификация ссылок** | Указывает, какую локальную ветку отправить в какую удаленную. <br> *Формат:* `<local_branch>:<remote_branch>`. Если имя не указано → используется имя локальной ветки. |

---
### 🚩 Ключевые флаги (Professional Options)

| Флаг                 | Полное имя       | Техническое назначение                                                                                               |
| :------------------- | :--------------- | :------------------------------------------------------------------------------------------------------------------- |
| `-u`                 | `--set-upstream` | Связывает локальную ветку с удаленной. В будущем позволяет делать `git push` и `git pull` без указания аргументов.   |
| `-f`                 | `--force`        | **Destructive.** Перезаписывает историю на сервере локальной историей. Игнорирует проверки на потерю коммитов.       |
| `--force-with-lease` | —                | **Safety Force.** Более безопасный вариант `-f`. Откажет в пуше, если кто-то другой успел обновить ветку на сервере. |
| `-d`                 | `--delete`       | Удаляет указанную ветку или тег непосредственно в удаленном репозитории.                                             |
| `--all`              | `--all`          | Отправляет все локальные ветки, для которых настроены соответствия в `.git/config`.                                  |
| `-v`                 | `--verbose`      | Выводит подробности: список передаваемых объектов, сжатие и итоговое состояние ссылок.                               |
| `--tags`             | `--tags`         | Отправляет все локальные теги из `refs/tags/` на сервер.                                                             |

### 🏗️ Внутренняя логика (Internals)

1. **Pre-push check:** Git проверяет, является ли локальная история прямым продолжением удаленной (если не используется `--force`).
2. **Object Packing:** Гит собирает все новые коммиты и файлы в компактный `.pack` файл.
3. **Transmission:** Пакет передается на сервер по протоколу SSH или HTTPS.
4. **Remote Update:** Удаленный сервер распаковывает объекты и обновляет свои файлы-указатели в `refs/heads/`.

### 🛠️ Сценарии использования (Best Practices)

> [!EXAMPLE] **Первая публикация ветки**
> 
> Создаем связь с сервером для удобной работы в будущем:
> 
> ```bash
> git push -u origin feature-login
> ```

> [!EXAMPLE] **Безопасная перезапись истории (после Rebase)**
> 
> Если ты почистил свои коммиты через `rebase -i` и хочешь обновить сервер, не удалив чужую работу:
> 
> ```bash
> git push origin feature-login --force-with-lease
> ```

> [!EXAMPLE] **Удаление ветки на сервере**
> 
> Когда фича закончена и влита в main:
> 
> ```bash
> git push origin --delete feature-login
> ```
