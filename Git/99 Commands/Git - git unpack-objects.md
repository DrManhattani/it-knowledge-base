# 📦 git unpack-objects

> [!ABSTRACT] Суть
> Используется для распаковки **pack-файла** (бинарный архив с кучей сжатых данных, который находится в `objects`). Необходимым условием является перемещение этого файла в любую другую папку, иначе распаковка не будет выполнена

---
### 🕵️ Разгадка тайны: Почему файл нужно перемещать?

Если `.pack` лежит внутри `.git/objects/pack/`, команда `git unpack-objects` не сработает.
> [!IMPORTANT] **Защита от дублирования**
> Git — фанат эффективности. Когда он видит pack-файл в своей «родной» папке, он считает, что **эти объекты уже известны репозиторию**. 
> * Чтобы не выполнять бессмысленную работу и не создавать конфликты с уже проиндексированными данными, `unpack-objects` просто игнорирует любые объекты, которые Git **уже видит** в текущих pack-файлах базы данных.
> * **Решение:** Нужно вынести `.pack` во временную папку (например, в корень проекта), тогда Git воспримет его как «внешние новые данные» и их распакует.

>[!IMPORTANT] Есть еще одна хитрость: 
>`unpack-objects` не распакует объект, если он **уже существует** в папке `.git/objects/` в виде «loose» (свободного) объекта. Гит всегда проверяет хеш перед записью, чтобы не плодить копии.

---
### 🛠️ Алгоритм использования

Если тебе нужно вручную вытащить объекты из архива:
1. **Найди архив:** Обычно они лежат в `.git/objects/pack/`.
2. **Перемести его:** Например, в корень репозитория.
3. **Запусти распаковку через конвейер (`pipe`):**
```bash
   cat my-data.pack | git unpack-objects
```

_Git прочитает поток байтов и создаст кучу мелких файлов в `.git/objects/`._

---
### 📊 Разница состояний

|**Состояние данных**|**Формат хранения**|**Плюсы**|
|---|---|---|
|**Loose Objects**|Один файл = один объект.|Быстрый доступ к конкретному файлу.|
|**Pack-files**|Один `.pack` = сотни объектов.|Экстремальное сжатие и экономия места.|

---
### 💡 Когда это используется?
- **При `git fetch` / `git push`:** Git передает данные пачками (`pack`), чтобы не слать тысячи мелких файлов по сети.
- **При `git gc` (Garbage Collector):** Git делает обратную операцию — собирает мелкие «loose» объекты в один компактный `.pack`.
- **При восстановлении данных:** Если база повреждена, `unpack-objects` помогает вручную «выпотрошить» уцелевшие архивы.
