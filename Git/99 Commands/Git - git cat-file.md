# 🛠️ git cat-file

> [!ABSTRACT] Суть
> Если `git hash-object` — это «вход» в базу данных, то `git cat-file` — это основной инструмент для извлечения данных. Она позволяет «распаковать» объект и посмотреть, что у него внутри, зная его хеш или указатель (например, HEAD).

>[!abstract] Синтаксис
>```bash
>git cat-file <mode> <object>
>```

---
## 🚩 1. Основные флаги (Key Flags)

> [!SETTINGS] Основные флаги `git cat-file` 🚩
> 
> | **Флаг** | **Mnemonic** | **Подробное описание** | **Пример использования** |
> | :--- | :--- | :--- | :--- |
> | `-t` | **T**ype | **Тип объекта.** Показывает, чем является объект: `blob`, `tree`, `commit` или `tag`. | `git cat-file -t HEAD` |
> | `-s` | **S**ize | **Размер.** Показывает размер объекта в байтах в несжатом виде. | `git cat-file -s d67046` |
> | `-p` | **P**retty-print | **Красивый вывод.** Выводит содержимое объекта в человекочитаемом формате. | `git cat-file -p HEAD` |

---

## 👨‍🍳 2. Полезные рецепты (Cookbook)

> [!EXAMPLE] Исследование указателей HEAD
> 
> Быстрая проверка того, на что указывает текущая ветка и её история.
> 
> ```bash
> git cat-file -t HEAD       # Узнать тип (обычно commit)
> git cat-file -p HEAD^      # Посмотреть содержимое родительского коммита
> ```

> [!TIP] Заглядываем в структуру проекта (Tree)
> 
> Если нужно увидеть список файлов, которые были зафиксированы в конкретном коммите.
> 
> ```bash
> git cat-file -p HEAD^{tree}
> ```

> [!IMPORTANT] Проверка конкретного файла (Blob)
> 
> Если у тебя есть хеш файла (из вывода дерева), ты можешь прочитать его текст напрямую.
> 
> ```bash
> git cat-file -p 83baae6106
> ```

> [!TIP] Навигация по HEAD 🧭
> В Git можно обращаться к объектам не только по хешу, но и через относительные ссылки:
> - `HEAD` — текущий коммит.
> - `HEAD~1` — предыдущий коммит (один шаг назад).
> - `HEAD~2` — коммит за два шага назад.
> - `HEAD^` — первый родитель текущего коммита.
> - `HEAD^{tree}` — дерево (список файлов) текущего коммита.
---

> [!GEAR] ⚙️ 3. Under the Hood (Внутреннее устройство)
> 
> Эта команда выполняет операцию, обратную `hash-object`. Она работает как «декомпрессор» и «парсер»:
> 
> 1. **Поиск** 🔍: Git ищет файл в `.git/objects/`, используя первые два символа хеша как имя папки.
> 2. **Распаковка** 🔓: Содержимое считывается и разжимается с помощью алгоритма **Zlib**.
> 3. **Чтение заголовка** 📋: Git отделяет технический заголовок (`тип` + `размер` + `\0`) от основного контента.
> 4. **Вывод** 🖥️: В зависимости от флага, Git выдает либо часть заголовка (`-t`, `-s`), либо только контент (`-p`).
>
> ### Логика извлечения контента:
> $$\text{Output} = \text{Decompress}_{\text{zlib}}(\text{ObjectFile}) - \text{Header}$$

> [!QUESTION] 🧠 4. В чём разница между `~` и `^` при слиянии (Merge)?
> 
> Когда мы работаем с обычным линейным коммитом, `HEAD~1` и `HEAD^` — это одно и то же. Но в **Merge Commit** (у которого два и более родителя) их пути расходятся:
> 
> 1. **Тильда (**`~`**) — это глубина (Depth)** 垂直: Она всегда идёт по «первой линии» предков (основная ветка). `HEAD~2` — это «дедушка» коммита по прямой линии. Т.е.  (`~`) всегда идет строго назад по цепочке «первых родителей». Это как прыжки по поколениям: отец, дед, прадед.
> 2. **Каретка (**`^`**) — это выбор родителя (Breadth)** 水平: Она выбирает конкретного **родителя** у одного и того же коммита.
>    - *У обычного коммита всего один родитель.* Поэтому `HEAD^` (или `HEAD^1`) сработает, а `HEAD^2` или `HEAD^3` выдадут ошибку — Git просто не видит второго или третьего отца у этого коммита.
>    - `HEAD^1` — первый родитель (та ветка, **В** которую вливали).
>    - `HEAD^2` — второй родитель (та ветка, которую вливали).
>    - `HEAD^3` сработает только в том случае, если текущий коммит — это результат **октопус-мержа** (слияния трех и более веток одновременно), что встречается довольно редко.
> ### 🗺️ Логика навигации:
> - *HEAD~n*: Переход на $n$ шагов назад строго по первым родителям.
> - *HEAD^n*: Переход на $n$-го родителя конкретного коммита.
> ### 🛠️ Как это работает в цепочке?
Самое интересное начинается, когда мы их комбинируем. Git читает их слева направо.
Например: `HEAD~2^2`
>1. Сначала прыгаем на 2 шага назад по прямой (`~2`). 
>2. Оказавшись там, выбираем **второго** родителя этого коммита (`^2`). То есть мы уходим в ветку, которую когда-то влили в основную.
