# 🧹 git clean

> [!ABSTRACT] **Определение**
> 
> `git clean` — это команда для удаления неотслеживаемых (untracked) файлов из рабочей директории. Она помогает привести проект в идеально «чистое» состояние, удаляя временные файлы, результаты сборки или ошибочно созданные документы.

---
### 🧱 Главный предохранитель

Git по умолчанию считает `git clean` чрезвычайно опасной командой, так как удаленные файлы нельзя восстановить через `reflog` (они не были в базе объектов).

- По умолчанию команда **не сработает**, если не передать флаг `-f` (force).
- В конфигурации Git за это отвечает параметр `clean.requireForce`. Если он стоит в `true` (это дефолт), команда без флагов выдаст ошибку.

---
### 🛠️ Таблица флагов (Инструментарий)

| **Команда**              | **Описание**                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| `git clean -n`           | **Dry Run.** Самый важный флаг. Показывает, что будет удалено, но ничего не удаляет.                               |
| `git clean -f`           | **Force.** Реальное удаление неотслеживаемых файлов.                                                               |
| `git clean -d`           | Удаляет не только файлы, но и **пустые директории**.                                                               |
| `git clean -x`           | Удаляет всё: и обычные untracked файлы, и те, что прописаны в `.gitignore`.                                        |
| `git clean -X`           | Удаляет **только** игнорируемые файлы (удобно для очистки `node_modules` или кеша).                                |
| `git clean -i`           | **Interactive.** Запускает меню, где можно поштучно выбрать файлы для удаления.                                    |
| `git clean -e <pattern>` | **Exclude.** Игнорировать определенный папки, даже которых нет в `.gitignore`. Например, `git clean -f -e "*.log"` |

---
### 🔍 Техническая разница: `clean` vs `reset --hard`

Это любимый «вопрос с подвохом» на интервью.

- **`git reset --hard`**: Возвращает **отслеживаемые** файлы к состоянию коммита. Она не трогает новые (untracked) файлы.
- **`git clean -fd`**: Удаляет **неотслеживаемые** файлы и папки. Она не трогает изменения в уже закоммиченных файлах.

> [!SUCCESS] **Pristine State**
> 
> Чтобы полностью привести проект к состоянию «как в репозитории», нужно выполнить связку:
> 
> `git reset --hard HEAD && git clean -fd`

### ❓ Вопросы на собеседовании

> [!IMPORTANT] **Популярные вопросы про очистку**
> 
> **1. Можно ли восстановить файлы после **`git clean`**?**
> 
> - **Ответ:** Нет. Поскольку файлы не были добавлены в индекс или коммит, Git не создал для них объектов в базе данных. Это одна из немногих операций в Git, после которой данные теряются безвозвратно.
>     
> 
> ---
> 
> **2. Как удалить только файлы, которые попали в **`.gitignore`**?**
> 
> - **Ответ:** Использовать флаг с большой буквой `X`: `git clean -fX`. Это часто нужно для пересборки проекта с нуля, когда нужно снести все скомпилированные бинарники.
>     
> 
> ---
> 
> **3. Что будет, если запустить **`git clean -f` **в папке, где лежат новые, созданные тобой файлы?**
> 
> - **Ответ:** Если ты их еще не добавил в индекс через `git add`, они будут немедленно удалены.
>     
> 
> ---
> 
> **4. Как заставить **`git clean` **игнорировать определенные папки, даже если они не в** `.gitignore`**?**
> 
> - **Ответ:** Можно использовать флаг `-e <pattern>` (exclude). Например: `git clean -f -e "*.log"`.
>     
> 
> ---
> 
> **5. Почему **`git clean` **не удаляет папки по умолчанию?**
> 
> - **Ответ:** Это еще один уровень защиты. Для удаления директорий нужно явно добавить флаг `-d`.
>

### 🎙️ Как ответить на собеседовании?

> «`git clean` — это инструмент для поддержания гигиены рабочего каталога. В отличие от `reset`, она работает с тем, что Git еще не контролирует. Я всегда начинаю с `git clean -n`, чтобы убедиться, что не удалю ничего лишнего, и часто использую `git clean -fxd` для полной очистки проекта от артефактов старых сборок и игнорируемых файлов перед важным релизом или сменой окружения».
