# 📋 git reflog

> [!ABSTRACT] **Техническое определение**
> 
> **git reflog** (Reference Log) — это механизм, который записывает все изменения указателей (HEAD, веток, тегов) в локальном репозитории. Он фиксирует каждое событие, когда верхушка какой-либо ветки перемещалась (из-за коммита, переключения веток, слияния или `reset`).

---
### 🏗️ Главное отличие: Log vs Reflog

|**Характеристика**|**git log**|**git reflog**|
|---|---|---|
|**Что показывает**|История **коммитов** (граф версии).|История **движений HEAD** и указателей.|
|**Видимость**|Публичная (видна всем после push).|**Локальная** (только на твоем ПК).|
|**Стабильность**|Можно изменить (rebase/amend).|Почти нельзя изменить (только со временем).|
|**Область**|Только то, что в текущей ветке.|**Всё**, что ты делал в репозитории за 90 дней.|

### 🛠️ Таблица команд и навигации

| **Команда**      | **Описание**                                  | **Пример**                   |
| ---------------- | --------------------------------------------- | ---------------------------- |
| `show` (Default) | Показывает лог перемещений HEAD.              | `git reflog`                 |
| `<ref>@{n}`      | Обращение к состоянию ссылки `n` шагов назад. | `git reset --hard HEAD@{2}`  |
| `delete`         | Удалить конкретную запись из лога.            | `git reflog delete HEAD@{0}` |
| `expire`         | Очистить старые записи (ручной запуск).       | `git reflog expire --all`    |

### 🔍 Ответы на технические вопросы

> [!QUESTION] **1. Где физически хранятся эти данные?**
> 
> Все записи лога хранятся в простых текстовых файлах внутри папки `.git/logs/`. Например, история HEAD лежит в `.git/logs/HEAD`, а история ветки main — в `.git/logs/refs/heads/main`.

> [!QUESTION] **2. Сколько живет запись в reflog?**
> 
> В Git есть встроенный механизм очистки (`git gc`). По умолчанию:
> 
> - Записи о **достижимых** коммитах хранятся **90 дней**.
>     
> - Записи о коммитах, которые стали «сиротами» (unreachable), хранятся **30 дней**.
>     
>     Это твое «окно возможностей» для спасения данных.
>     

> [!QUESTION] **3. Сохраняет ли reflog данные, которые я НЕ закоммитил?**
> 
> **Нет.** Reflog записывает изменения **указателей**. Если ты просто менял код в файлах и не делал ни `git commit`, ни `git stash`, ни `git add`, — в reflog ничего не попадет. Он видит только завершенные операции Git.

### 🚑 Сценарии спасения (Best Practices)

#### Сценарий А: Отмена `git reset --hard`

Ты сделал «жесткий сброс» и понял, что стер нужные коммиты. В `git log` их больше нет.

1. Пишем `git reflog`.
2. Находим строку перед ресетом (например, `HEAD@{1}`).
3. Пишем `git reset --hard HEAD@{1}`.
    **Результат:** Ты вернулся в будущее.
#### Сценарий Б: Восстановление удаленной ветки

Ты удалил ветку `feature` через `git branch -D`.

1. Пишем `git reflog`.
2. Ищем последний коммит в этой ветке (там будет запись вроде `checkout: moving from feature to main`).
3. Берем хеш этого коммита.
4. Пишем `git branch feature <hash>`.
    **Результат:** Ветка восстановлена со всеми коммитами.

### ❓ Вопросы на собеседовании

> [!IMPORTANT] **Популярные вопросы про "Черный ящик"**
> 
> **1. Можно ли восстановить коммит, если был сделан **`git commit --amend`**?**
> 
> - _Ответ:_ Да. При аменде Git создает новый коммит, а старый «отбрасывает». Reflog зафиксирует это перемещение HEAD, и ты сможешь найти хеш «оригинального» коммита до того, как ты его изменил.
>     
> 
> ---
> 
> **2. Увидит ли мой коллега мой reflog, если я сделаю **`push`**?**
> 
> - _Ответ:_ Нет. Reflog — это сугубо локальный журнал. Он отражает твою личную работу с репозиторием. На сервере у каждой копии репозитория свой собственный reflog.
>     
> 
> ---
> 
> **3. В чем разница между **`HEAD@{1}` **и** `HEAD~1`**?**
> 
> - _Ответ:_ Это критический вопрос.
>     
>     - `HEAD~1` — это **родитель** текущего коммита (история кода).
>         
>     - `HEAD@{1}` — это **предыдущее положение** указателя HEAD (твое действие).
>         
>         Если ты только что переключился с ветки `A` на ветку `B`, `HEAD@{1}` укажет на верхушку ветки `A`, а `HEAD~1` укажет на коммит ниже текущего в ветке `B`.
>         
> 
> ---
> 
> **4. Как почистить reflog вручную, если в нем секретные данные?**
> 
> - _Ответ:_ `git reflog expire --expire=now --all` и затем запустить сборщик мусора `git gc --prune=now`.
>
