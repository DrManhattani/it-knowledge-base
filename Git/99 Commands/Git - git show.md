# 🔍 git show

> [!ABSTRACT] **Определение**
> 
> **git show** — это универсальный «просмотрщик» объектов. Чаще всего её используют для изучения содержимого конкретного коммита (его метаданных и разницы в коде), но технически она может отобразить любой объект из базы данных `.git/objects`.

---
### 🛠️ Таблица флагов и вариантов использования

| **Флаг / Аргумент** | **Описание**                                                                       | **Пример**                 |
| ------------------- | ---------------------------------------------------------------------------------- | -------------------------- |
| **(без флагов)**    | Показывает данные последнего коммита (**HEAD**).                                   | `git show`                 |
| `<hash>`            | Детальный просмотр конкретного коммита.                                            | `git show a1b2c3d`         |
| `--stat`            | Вместо полного кода показывает только список измененных файлов и количество строк. | `git show --stat`          |
| `<ref>:<path>`      | **Магия:** Показывает содержимое файла в конкретной ветке или коммите.             | `git show main:README.md`  |
| `--format`          | Позволяет настроить вывод (показать только автора, только дату и т.д.).            | `git show -s --format=%ae` |
| `-s` (`--no-patch`) | Скрывает diff (разницу в коде), оставляя только метаданные (автор, сообщение).     | `git show -s <hash>`       |

---
### 🏗️ Что именно можно «показать»? (Объектный уровень)

Git — это контентно-адресуемое хранилище. `git show` понимает это буквально:

1. **Коммиты:** Показывает автора, дату, сообщение и `diff`.
2. **Теги:** Если это «аннотированный тег», покажет сообщение тега и коммит, на который он указывает.
3. **Деревья (Trees):** Покажет список файлов и папок внутри (через `git show <hash_of_tree>`).
4. **Блобы (Blobs):** Просто выведет содержимое файла в терминал.

### 🔍 Ответы на технические вопросы

> [!QUESTION] **1. В чем разница между **`git show` **и** `git log -p -1`**?**
> 
> **Ответ:** Результат для коммита будет идентичным. Однако `git log` предназначен для работы с **цепочками** коммитов (историей), а `git show` ориентирован на **конкретный объект**. Кроме того, `show` умеет показывать теги и файлы напрямую, чего `log` не делает.

> [!QUESTION] **2. Как посмотреть только список файлов в коммите без кода?**
> 
> **Ответ:** `git show --name-only <hash>`. Если нужна еще и статистика (сколько строк добавлено/удалено) — `git show --stat <hash>`.

> [!QUESTION] **3. Как с помощью **`show` **увидеть, что было изменено в файле 3 коммита назад?**
> 
> **Ответ:** `git show HEAD~3:path/to/file.py`. Это выведет **весь** файл в том состоянии. Если нужен именно diff того коммита, то `git show HEAD~3`.

### ❓ Вопросы на собеседовании

> [!IMPORTANT] **Популярные вопросы про Инспекцию**
> 
> **1. Как проверить содержимое аннотированного тега?**
> 
> - _Ответ:_ `git show <tag_name>`. Это покажет, кто создал тег, когда, и какое сообщение оставил, в отличие от простого `git tag`, который выводит только имя.
>     
> 
> ---
> 
> **2. Как посмотреть, какие изменения внес коммит в конкретный файл, не листая весь diff?**
> 
> - _Ответ:_ `git show <hash> -- <path/to/file>`. Это отфильтрует вывод `show` только по указанному пути.
>     
> 
> ---
> 
> **3. Что такое формат Unified Diff, который выводит **`git show`**?**
> 
> - _Ответ:_ Это стандарт отображения изменений, где `---` — старая версия, `+++` — новая, а строки начинающиеся с `-` и `+` показывают удаление и добавление соответственно. `@ -1,5 +1,6 @@` — это чанки (hunks), указывающие на координаты строк.
>     
> 
> ---
> 
> **4. Как вывести только хеш родителя конкретного коммита?**
> 
> - _Ответ:_ `git show -s --format=%P <hash>`. Флаг `-s` уберет diff, а формат `%P` (Parent) достанет только нужные метаданные.
>

### 💡 Резюме для интервьюера

> «`git show` — мой основной инструмент для "быстрого погружения". Если я вижу подозрительный коммит в `git log`, я использую `show`, чтобы мгновенно увидеть контекст изменений. Также я часто использую синтаксис `show <branch>:<file>`, чтобы сравнить текущий код с версией из другой ветки, не переключаясь на неё (без `checkout`)».
