# 📖 Руководство: Git Switch

### 1. Техническое определение

>[!ABSTRACT]  Определение
>**git switch** — это команда, которая предназначена для переключения между ветками и создания новых. В отличие от `checkout`, она не умеет восстанавливать файлы, что делает её использование более безопасным (вы не перезапишете файл случайно, пытаясь перейти на ветку с похожим именем).

---

### 2. Работа «под капотом»: Механика перехода

Когда вы выполняете `git switch <branch>`, Git выполняет следующие действия:

1. **Проверка чистоты (Safety Check):** Git проверяет, не приведет ли переход к потере незакоммиченных данных. Если ваши локальные изменения конфликтуют с целевой веткой, команда прервется.
2. **Обновление HEAD:** Файл `.git/HEAD` обновляется и теперь содержит путь к новой ветке (например, `ref: refs/heads/feature`).
3. **Синхронизация индекса и дерева:** Индекс (Stage) и рабочая директория обновляются, чтобы соответствовать состоянию целевого коммита.
4. **Установка Upstream:** Если ветка создается из удаленной, Git автоматически прописывает связь (tracking) в конфигурационном файле.

### 3. Таблица флагов git switch

| **Флаг (+ полный)**          | **Описание механики и логика работы**                                                                                                              | **Примеры**                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| `-c`<br><br>`--create`       | **Создание и переход.** Аналог `checkout -b`. Создает новый указатель ветки и перемещает туда `HEAD`.                                              | `git switch -c new-feature`  |
| `-C`<br><br>`--force-create` | **Силовой сброс.** Если ветка существует, она будет принудительно переставлена на текущий коммит, а вы переключены на неё.                         | `git switch -C main`         |
| `-d`<br><br>`--detach`       | **Отсоединенный HEAD.** Переключает вас на конкретный коммит без привязки к ветке. Полезно для изучения истории или временных тестов.              | `git switch -d HEAD~3`       |
| `-m`<br><br>`--merge`        | **Трехстороннее слияние.** Если у вас есть локальные правки, Git попытается объединить их с кодом целевой ветки прямо в процессе перехода.         | `git switch -m master`       |
| `--orphan`                   | **Ветка без предков.** Создает ветку с пустой историей. Все текущие файлы остаются в индексе, готовые стать первым коммитом.                       | `git switch --orphan docs`   |
| `-t`<br><br>`--track`        | **Явная привязка.** Создает локальную ветку на основе удаленной и настраивает автоматический `push/pull`.                                          | `git switch -t origin/dev`   |
| `--guess / --no-guess`       | **Умный поиск.** По умолчанию включен. Если локальной ветки нет, но есть одна удаленная с таким именем, Git создаст локальную ветку автоматически. | `git switch feature-x`       |
| `--discard-changes`          | **Сброс балласта.** Переключает ветку, даже если есть локальные изменения (они будут безвозвратно удалены).                                        | `git switch -f main` (alias) |

### 4. Гранд-сравнение: Switch vs Checkout

|**Ситуация**|**git switch**|**git checkout**|
|---|---|---|
|**Переход на ветку**|`git switch branch`|`git checkout branch`|
|**Создание ветки**|`git switch -c branch`|`git checkout -b branch`|
|**Восстановление файла**|**Не умеет** (ошибка)|`git checkout -- file.txt`|
|**Безопасность**|Высокая (не путает файлы и ветки)|Средняя (риск затереть файл)|
|**Mental Model**|"Я меняю ветку"|"Я меняю состояние"|

### 5. Нюансы и продвинутый функционал

#### Автоматический "Guessing" (Умное угадывание)

Если вы пишете `git switch fix-bug`, а локально такой ветки нет, Git не выдаст ошибку сразу. Он заглянет во все `remotes`. Если он найдет `origin/fix-bug`, он сам создаст локальную ветку `fix-bug` и настроит трекинг. Это избавляет от длинных команд типа `git checkout -b fix-bug origin/fix-bug`.

#### Возврат назад

Команда `git switch -` (с дефисом) мгновенно возвращает вас на предыдущую ветку, где вы были до этого. Это работает через `@{-1}`.

### 6. Вопросы с собеседований

#### 🟢 Junior (База)

- **Зачем нужен `git switch`, если есть `checkout`?**
    
    - _Ответ:_ Для разделения ответственности. `switch` предназначен только для веток, что исключает случайную перезапись файлов и делает API команды более интуитивным.
    
- **Как создать ветку на основе конкретного коммита?**
    
    - _Ответ:_ `git switch -c <branch_name> <commit_hash>`.

#### 🟡 Middle (Инструментарий)

- **Что произойдет, если попытаться сделать `switch` с грязным рабочим деревом?**
    
    - _Ответ:_ Git проверит, затрагивают ли ваши изменения те же файлы, что и в целевой ветке. Если да — команда прервется. Вы сможете пройти только с флагом `-m` (слияние) или спрятав изменения в `stash`.
        
- **Как работает режим `--orphan` и где он применяется?**
    
    - _Ответ:_ Он создает ветку без истории. Применяется для GitHub Pages, документации или когда нужно начать проект заново в том же репозитории, сохранив текущие файлы как базу.

#### 🔴 Senior (Архитектура)

- **Какая низкоуровневая (plumbing) команда вызывается под капотом `switch`?**
    
    - _Ответ:_ В основном это `git update-ref` для обновления `HEAD` и `git read-tree` для обновления индекса и рабочей директории.
        
- **Как `git switch` взаимодействует с подмодулями (submodules)?**
    
    - _Ответ:_ По умолчанию `switch` не обновляет подмодули. Для этого нужно использовать флаг `--recurse-submodules`, иначе подмодули останутся на старых коммитах, что может привести к несогласованности кода.
