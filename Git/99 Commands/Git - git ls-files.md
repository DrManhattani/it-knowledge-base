# 🛠️ git ls-files

> [!ABSTRACT] Суть
> Если база объектов — это хранилище, то **Индекс** — это список того, что Git планирует включить в следующий коммит. `git ls-files` позволяет просмотреть этот «бинарный список» в удобном текстовом виде, а также проверить файлы, которые еще не попали под контроль Git.

>[!abstract] Синтаксис
>```bash
>git ls-files [<options>]
>```

---

## 🚩 1. Основные флаги (Key Flags)

> [!SETTINGS] Основные флаги `git ls-files` 🚩
> | **Флаг** | **Mnemonic** | **Подробное описание** | **Пример использования** |
> | :--- | :--- | :--- | :--- |
> | `-s`, `--stage` | **Stage** | Показывает подробную информацию об объектах в индексе: права доступа, SHA-1 хеш, номер стадии и имя файла. | `git ls-files -s` |
> | `-o`, `--others` | **Others** | Выводит список файлов, которые еще не отслеживаются Git (untracked). | `git ls-files -o` |
> | `-d`, `--deleted` | **Deleted** | Показывает файлы, удаленные из рабочей директории, но все еще числящиеся в индексе. | `git ls-files -d` |
> | `-i`, `--ignored` | **Ignored** | Выводит файлы, которые Git игнорирует согласно правилам `.gitignore`. | `git ls-files -i --others` |
> | `-u`, `--unmerged` | **Unmerged** | Показывает файлы с конфликтами слияния, требующие ручного разрешения. | `git ls-files -u` |

---

## 👨‍🍳 2. Полезные рецепты (Cookbook)

> [!EXAMPLE] Поиск хеша конкретного файла в индексе
> Если нужно быстро узнать текущий хеш версии файла, которая готова к коммиту.
> ```bash
> git ls-files -s path/to/file.txt
> ```

> [!TIP] Проверка чистоты .gitignore
> Позволяет убедиться, что файлы, которые вы хотели игнорировать, действительно не отслеживаются.
> ```bash
> git ls-files -i -o --exclude-standard
> ```

## ⚙️ 3. Under the Hood (Внутреннее устройство)

> [!GEAR] Файл .git/index 🗃️
> На самом деле индекс — это не папка, а один бинарный файл, расположенный в `.git/index`. 
> 
> 1. **Структура**: Каждая запись в индексе содержит путь к файлу и SHA-1 хеш соответствующего блоба (blob) в базе объектов.
> 2. **Связь**: Команда `ls-files` считывает этот файл и сопоставляет его данные с текущим состоянием файлов на диске (Working Directory).
> 3. **Скорость**: Благодаря индексу Git не нужно сканировать все файлы проекта при каждом `git status` — он просто сравнивает метаданные из индекса с файлами на диске.

## 🧠 4. Deep Dive / Question

> [!QUESTION] Что означают цифры "стадий" в выводе `git ls-files -s`?
> При выполнении `git ls-files -s` вы увидите число перед именем файла (обычно `0`). В нормальном состоянии это `0`. Однако во время **конфликта слияния** один и тот же файл может появиться трижды:
> - **1**: Общий предок (Base).
> - **2**: Ваша текущая версия (Ours/HEAD).
> - **3**: Версия, которую вы вливаете (Theirs/Remote).

> [!DANGER] Ошибка: fatal: ls-files --ignored needs some exclude pattern
> 
> Эта ошибка возникает, когда флаг `-i` (или `--ignored`) используется без указания источника правил игнорирования. Git не знает «автоматически», какие именно файлы считать игнорируемыми для этой команды.
> 
> ### 🛠️ Решение
> Чтобы команда заработала, нужно добавить флаг `--exclude-standard`, который указывает Git использовать стандартные файлы исключений (`.gitignore`, `.git/info/exclude` и глобальный конфиг).
> 
> ```bash
> git ls-files -i --others --exclude-standard
> ```

> [!QUESTION] Почему команда может ничего не выводить?
> 
> Даже если в `.gitignore` прописаны правила, `ls-files` может выдать пустой результат по двум причинам:
> 
> 1. **Файлы уже отслеживаются (Tracked)** ⚓: Если файл был добавлен в индекс (`git add`) **до** того, как правило появилось в `.gitignore`, Git продолжает его отслеживать. Флаг `--others` ищет только среди «чужих» (неотслеживаемых) файлов.
> 2. **Файлы отсутствуют на диске** 🕳️: Если папка, указанная в `.gitignore`, физически пуста, Git её «не видит» и не выводит в списке.
