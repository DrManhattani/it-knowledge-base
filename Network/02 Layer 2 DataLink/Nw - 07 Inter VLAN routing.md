# 🌐 Суть Inter-VLAN Routing

По умолчанию устройства в разных VLAN находятся в изолированных широковещательных доменах (L2). Они не могут общаться друг с другом, даже если физически подключены к одному коммутатору. Чтобы связать эти «облака», необходим процесс маршрутизации на уровне **L3**.

> [!IMPORTANT] **Ключевая концепция**
> 
> Чтобы пакет покинул свою сеть (VLAN), он должен быть отправлен на **Default Gateway** (шлюз по умолчанию). Шлюз должен иметь интерфейсы во всех сетях, которые он планирует связывать.

---

### 🛠 Способы реализации маршрутизации

|**Способ**|**Описание**|**Плюсы/Минусы**|
|---|---|---|
|**Router-on-a-Stick**|Один физический линк между L2-свитчем и роутером (Trunk). На роутере создаются саб-интерфейсы.|➖ "Узкое горлышко" (один линк на все VLAN).|
|**L3 Switch (SVI)**|Маршрутизация происходит внутри коммутатора на виртуальных интерфейсах.|➕ Высокая скорость (Hardware-based), трафик не покидает свитч.|
|**Routed Ports**|Порт коммутатора превращается в порт роутера (`no switchport`).|➕ Прямая связь "точка-точка" между L3-устройствами.|

### 🧩 Механика L3-коммутатора: SVI (Switch Virtual Interface)

Внутри L3-коммутатора сосуществуют две сущности: **L2-матрица** (VLAN-ы) и **L3-движок** (виртуальный маршрутизатор).

- **SVI (Interface VLAN):** Это виртуальный порт, который «пристегивает» конкретный VLAN к внутреннему маршрутизатору.
- Для хостов в сети этот интерфейс становится шлюзом (Gateway).

> [!NOTE] **SVI на L2 vs L3 свитчах**
> 
> - На **L2 (2960)**: SVI нужен только для **управления** (менеджмент IP). Свитч может иметь только один активный IP и не умеет перебрасывать пакеты между VLAN.
>     
> - На **L3 (3560/3750/3850)**: SVI работает как полноценный шлюз. Можно создать десятки интерфейсов, и свитч будет маршрутизировать трафик между ними.
>

### 📝 Алгоритм настройки (Cisco CLI)

Чтобы L3-коммутатор начал работать как роутер, недостаточно просто дать IP-адреса.

#### 1. Глобальная активация

```bash
L3-Switch(config)# ip routing
```

_Без этой команды свитч будет просто устройством с несколькими IP-адресами управления, но не будет пересылать пакеты между ними._

#### 2. Создание шлюзов (SVI)

```bash
L3-Switch(config)# interface vlan 10
L3-Switch(config-if)# ip address 10.10.10.1 255.255.255.0
L3-Switch(config-if)# no shutdown

L3-Switch(config)# interface vlan 20
L3-Switch(config-if)# ip address 10.10.20.1 255.255.255.0
```

#### 3. Настройка L2-свитчей (Management)

Для обычных свитчей доступа нужно указать, куда слать трафик управления, если админ подключается из другой сети:

```bash
L2-Switch(config)# ip default-gateway 10.10.90.1
```

### 🕵️ Диагностика: Traceroute и TTL

**Traceroute** — основной инструмент DevOps/Админа для поиска места разрыва маршрута.

#### Принцип работы (Механизм TTL):

1. Отправляется пакет с **TTL=1**. Первый маршрутизатор (шлюз) уменьшает TTL до 0, отбрасывает пакет и шлет ответ `ICMP Time Exceeded`. Мы узнаем адрес первого хопа.
2. Отправляется пакет с **TTL=2**. Он проходит первый хоп и умирает на втором. Мы узнаем адрес второго хопа.
3. Процесс повторяется, пока не ответит целевой узел.

> [!TIP] **Различия ОС**
> 
> - **Windows **(`tracert`): Использует ICMP Echo Requests.
>     
> - **Linux/Cisco **(`traceroute`): По умолчанию использует UDP-пакеты на высокие порты.
>     
> - _Если вы видите `* * *` в выводе — значит, устройство на этом этапе блокирует ICMP-ответы (Firewall)._
>

### 🐧 DevOps & Linux Context

В мире Linux-администрирования концепция **SVI** аналогична созданию VLAN-интерфейсов на сервере, который выполняет роль шлюза.

- **Linux Gateway:** Если ваш Linux-сервер должен маршрутизировать трафик между `eth0.10` и `eth0.20`, вы должны включить аналог команды `ip routing`:    
```bash
    sysctl -w net.ipv4.ip_forward=1
```
- **Трассировка:** В Linux используйте `traceroute -n` (чтобы не ждать резолва имен) или `mtr` (My Traceroute) — это комбинация ping и traceroute, которая показывает статистику потерь на каждом узле в реальном времени.
