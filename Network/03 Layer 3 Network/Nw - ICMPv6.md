# 🏓 ICMPv6: Фундамент сетей нового поколения

## 📑 NAME

**ICMPv6** — это не просто обновленная утилита `ping`. В сетях IPv6 этот протокол получил "режим Бога". Он поглотил в себя функции старого ARP (поиск MAC-адресов), IGMP (управление мультикастом) и даже часть функций DHCP (автоконфигурация адресов).

> [!DANGER] **Главное правило архитектора**
> 
> В IPv4 отключение ICMP было плохой идеей. В IPv6 отключение ICMPv6 **полностью уничтожит сеть**. Без него хосты не смогут получить IP-адреса, не узнают MAC-адреса соседей и не смогут маршрутизировать трафик.

## ⚙️ ARCHITECTURE & PROTOCOL SPECS

- **OSI Layer:** L3 (Сетевой уровень).
- **Транспорт:** Инкапсулируется напрямую в IPv6-пакет. В базовом заголовке IPv6 поле **Next Header** для ICMPv6 равно **58**.
- **Смерть Broadcast:** В IPv6 полностью упразднено понятие широковещательного трафика (Broadcast). Все рассылки "всем-всем-всем" теперь делаются через умный **Multicast** (многоадресную рассылку).

Структура сообщений ICMPv6 жестко разделена на два лагеря старшим битом в поле _Type_:

1. **Типы от 0 до 127:** Сообщения об ошибках (Error Messages).
2. **Типы от 128 до 255:** Информационные сообщения (Informational Messages).

### 🔴 Ошибки доставки (Type 0-127)

|**Type**|**Code**|**Имя (Функция)**|**Инженерный смысл**|
|---|---|---|---|
|**1**|0-7|**Destination Unreachable**|Аналог из IPv4. Нет маршрута, запрещено файрволом, не отвечает порт.|
|**2**|0|**Packet Too Big (PTB)**|⚠️ **Архитектурный столб IPv6**. Сообщает, что пакет превышает MTU линка.|
|**3**|0, 1|**Time Exceeded**|Истек Hop Limit (аналог TTL в IPv4). База для `traceroute6`.|
|**4**|0-2|**Parameter Problem**|Ошибка в синтаксисе заголовка IPv6 (например, неизвестный Next Header).|

> [!WARNING] **Почему Type 2 (Packet Too Big) критически важен?**
> 
> В IPv4 промежуточные маршрутизаторы умели "на лету" фрагментировать большие пакеты. **В IPv6 роутерам это строго запрещено** ради экономии ресурсов CPU. Фрагментировать пакет имеет право только отправитель!
> 
> Протокол **PMTUD (Path MTU Discovery)** в IPv6 стал обязательным. Если ваш файрвол заблокирует ICMPv6 Type 2, сервер никогда не узнает, что нужно уменьшить размер пакета, и тяжелый трафик (TCP/TLS-сессии, скачивание файлов) просто зависнет.

### 🟢 Информационные сообщения и NDP (Type 128-255)

Это та самая магия, которая делает IPv6 "plug-and-play" протоколом.

|**Type**|**Имя сообщения**|**Расшифровка функции**|
|---|---|---|
|**128**|**Echo Request**|Классический `ping6`. Запрос.|
|**129**|**Echo Reply**|Классический `ping6`. Ответ.|
#### 🧠 Механизм NDP (Neighbor Discovery Protocol)

Заменяет ARP и позволяет хостам находить друг друга в подсети.

|**Type**|**Имя сообщения**|**Как это заменяет ARP и DHCP**|
|---|---|---|
|**133**|**Router Solicitation (RS)**|Хост только что включился и кричит (Multicast): _"Эй, роутеры! Вы тут есть? Дайте мне параметры сети!"_.|
|**134**|**Router Advertisement (RA)**|Роутер отвечает: _"Я тут. Вот твой префикс сети (например, 2001:db8::/64), вот твой шлюз по умолчанию. Генерируй IP сам"_. (Это называется **SLAAC** — Stateless Address Autoconfiguration).|
|**135**|**Neighbor Solicitation (NS)**|Замена ARP-запроса. _"У кого IPv6-адрес 2001:db8::10? Скажи свой MAC!"_. Отправляется не всем (не Broadcast), а на специальный Multicast-адрес (Solicited-Node).|
|**136**|**Neighbor Advertisement (NA)**|Замена ARP-ответа. _"Это мой IP. Мой MAC-адрес: aa:bb:cc:dd:ee:ff"_.|

## 🔬 ГЛУБОКОЕ ПОГРУЖЕНИЕ: DAD и Solicited-Node Multicast

Собеседования на Middle/Senior Network Engineer или Cloud Architect часто затрагивают две неочевидные механики ICMPv6.
### 1. DAD (Duplicate Address Detection)

Когда компьютер сам себе придумывает IPv6-адрес (через SLAAC), он должен убедиться, что такого адреса больше ни у кого нет.

- Хост отправляет пакет **Neighbor Solicitation (Type 135)** с вопросом _"У кого есть этот IP?"_, но в качестве Source IP указывает специальный адрес `::` (Unspecified).
- Если в ответ прилетает **Neighbor Advertisement (Type 136)**, значит адрес занят. Хост помечает его как "Duplicate" и отключает интерфейс.
### 2. Solicited-Node Multicast Address (Как работает поиск соседей без спама)

В IPv4 ARP-запрос летит Broadcast'ом `FF:FF:FF:FF:FF:FF`. Это заставляет **каждый** компьютер в сети отвлечь CPU, принять пакет, прочитать его и понять: _"А, это не мой IP, удаляю"_. В огромных ЦОДах это создает фон широковещательного шторма.

В IPv6 используется хирургический подход:

- ОС берет последние 24 бита нужного IPv6-адреса.
- Приклеивает их к специальному префиксу `FF02::1:FFXX:XXXX`.
- Получается уникальный Multicast-адрес. ARP-запрос (точнее, NS) летит только на него. Сетевые карты других серверов даже не просыпаются, так как этот Multicast-адрес не совпадает с их собственным.
## 🛡️ DEVSEC / FIREWALL BEST PRACTICES (RFC 4890)

Как правильно фильтровать ICMPv6 на Linux серверах (iptables/ip6tables/nftables), чтобы не сломать сеть:

**Абсолютно запрещено блокировать:**

1. Весь трафик с Link-Local адресов (`fe80::/10`).
2. Сообщения об ошибках: `Type 1`, `Type 2` (Packet Too Big), `Type 3`, `Type 4`.
3. Сообщения NDP: `Type 133`, `Type 134`, `Type 135`, `Type 136`.
4. Базовый пинг (по желанию безопасности, но рекомендуется оставлять): `Type 128`, `Type 129`.

## 💻 CONFIGURATION & CLI (Linux / Cisco)

POSIX-стандарт для траблшутинга ICMPv6-инфраструктуры.

```bash
# === LINUX СЕРВЕР ===

# 1. Просмотр "ARP-таблицы" (IPv6 Neighbor Cache)
# Покажет IP соседей, их MAC-адреса и статус (REACHABLE / STALE)
$ ip -6 neigh show

# 2. Пинг Link-Local адреса соседа
# ВАЖНО: Для fe80:: адресов ВСЕГДА нужно указывать интерфейс исходящего трафика (через %),
# так как такие адреса одинаковы во всех сетях.
$ ping6 fe80::a1b2:c3ff:fe44:5566%eth0

# 3. Трассировка с использованием ICMPv6
$ traceroute6 -I google.com

# 4. Диагностика NDP-трафика в реальном времени (отлов NS/NA пакетов)
$ tcpdump -i eth0 icmp6

# === CISCO IOS ===

# 5. Включить маршрутизацию IPv6 (без нее роутер не будет отвечать на RS-запросы)
Priv # ipv6 unicast-routing

# 6. Просмотр таблицы соседей
Priv # show ipv6 neighbors

# 7. Дебаг процесса автоматической выдачи префиксов (SLAAC / RA)
Priv # debug ipv6 nd
```
