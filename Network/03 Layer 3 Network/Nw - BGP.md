# 🌐 BGP: Инженерный конспект

## 📑 NAME

**BGP (Border Gateway Protocol)** — протокол динамической маршрутизации внешнего шлюза (EGP). Де-факто является кровеносной системой всего интернета. В отличие от OSPF/EIGRP (IGP), которые ищут _самый быстрый_ путь внутри сети, BGP ищет _самый правильный с точки зрения политик_ путь между Автономными Системами (AS).

## ⚙️ ARCHITECTURE & PROTOCOL SPECS

- **Класс протокола:** Path-Vector (Вектор пути). Маршрут описывается как список пройденных AS.
- **Транспорт:** TCP, порт **179**. (Надежная доставка, нет необходимости в собственных механизмах фрагментации и подтверждений, как у OSPF).
- **Метрика:** Отсутствует единая метрика. Решения принимаются на основе **Атрибутов (Path Attributes)**.
- **Автономная Система (AS):** Логическое объединение маршрутизаторов под единым техническим управлением. Номера AS бывают 16-битные (1-65535) и 32-битные (расширенные).
    - _Приватные ASN:_ 64512 - 65534 (аналог серых IP-адресов, не маршрутизируются в интернете).

## 🌍 ВЕРСИИ: eBGP vs iBGP

BGP бывает двух видов, в зависимости от того, с кем устанавливается соседство (Peering):

|**Характеристика**|**eBGP (External)**|**iBGP (Internal)**|
|---|---|---|
|**Соседи**|Роутеры в _разных_ AS.|Роутеры в _одной_ AS.|
|**TTL пакетов**|По умолчанию `1` (соседи должны быть соединены напрямую).|По умолчанию `255` (соседи могут быть где угодно внутри сети).|
|**Изменение AS-Path**|Добавляет свой ASN в маршрут при отправке.|**НЕ** меняет AS-Path.|
|**Loop Prevention**|Если видит свой ASN в AS-Path — отбрасывает маршрут.|**Split Horizon:** Маршрут, полученный от iBGP-соседа, запрещено передавать другому iBGP-соседу.|

> [!DANGER] **Проблема iBGP Split Horizon**
> 
> Из-за правила запрета ретрансляции (Split Horizon) все iBGP-роутеры внутри одной AS обязаны быть соединены по принципу **Full Mesh** (Каждый с каждым). В крупных сетях это невозможно (формула $N(N-1)/2$).
> 
> **Решение:** Использование технологий **Route Reflector (RR)** или **BGP Confederations**.

## 📩 MESSAGE TYPES (Типы пакетов)

1. **OPEN:** Отправляется сразу после установки TCP-сессии (3-way handshake). Содержит версию BGP, ASN, Router ID и параметры (Hold Time, Capabilities).
2. **KEEPALIVE:** Поддерживает TCP-сессию. По умолчанию отправляется каждые 60 секунд. Если не приходит 180 секунд (Hold Timer), сосед считается мертвым.
3. **UPDATE:** Главный рабочий пакет. Содержит новые маршруты (NLRI - Network Layer Reachability Information), их атрибуты и список отозванных (мертвых) маршрутов (Withdrawn Routes).
4. **NOTIFICATION:** Фатальная ошибка. Отправляется при несовпадении таймеров, номеров AS или неверном формате пакета. Сразу после отправки рвет TCP-сессию.

## 🧠 STATE MACHINE (Жизненный цикл соседа)

Утилита `show ip bgp summary` всегда показывает текущее состояние FSM (Finite State Machine).

1. **Idle:** Стартовое состояние. Роутер ищет маршрут до IP-адреса соседа.
2. **Connect:** Идет попытка установить TCP-соединение (SYN -> SYN/ACK -> ACK) на порт 179.
3. **Active:** TCP-сессия упала. Роутер активно пытается поднять ее снова. _(Частая ошибка: забыли прописать маршрут до Loopback'а соседа)._
4. **OpenSent:** TCP установлен, отправлен пакет `OPEN`. Ждем `OPEN` от соседа.
5. **OpenConfirm:** Параметры в `OPEN` совпали. Ждем первого `KEEPALIVE`.
6. **Established:** 👑 Успех. Соседство поднято, начинается обмен таблицами маршрутизации (`UPDATE`).

## ⚖️ BEST PATH SELECTION ALGORITHM (Святой Грааль BGP)

Если BGP получает два пути до одной и той же сети (например, `8.8.8.0/24` от Провайдера А и Провайдера Б), он **не балансирует** трафик по умолчанию. Он выбирает только **один** лучший путь, прогоняя атрибуты через жесткий алгоритм сверху вниз.

_Мнемоника:_ **W**e **L**ove **O**ranges **AS** **O**ranges **M**ean **P**ure **R**efreshment.

1. **Weight (Вес):** Проприетарный атрибут Cisco. Локальный для роутера. **Больше = Лучше.**
2. **Local Preference:** Главный инструмент балансировки исходящего трафика внутри AS. Передается всем iBGP-соседям. (По умолчанию 100). **Больше = Лучше.**
3. **Originate:** Предпочтение отдается маршрутам, сгенерированным локально на этом роутере (командой `network` или редистрибьюцией).
4. **AS-Path:** Длина пути автономных систем. **Короче = Лучше.** (Часто используют _AS-Path Prepending_ для искусственного удлинения пути и снижения приоритета).
5. **Origin:** Тип происхождения. IGP (`i`) лучше, чем EGP (`e`), лучше, чем Incomplete (`?`).
6. **MED (Multi-Exit Discriminator):** Инструмент для указания соседней AS, в какой из линков лучше отправлять входящий трафик. **Меньше = Лучше.** (По умолчанию 0).
7. **Path Type:** Маршрут от eBGP-соседа предпочитается маршруту от iBGP-соседа.
8. **Router ID:** Выигрывает роутер с наименьшим BGP Router ID.

## 💻 CONFIGURATION (Cisco IOS Man-Page)

Базовый стандарт поднятия eBGP-соседства между двумя корпоративными линками.

```bash
# 1. Запуск процесса BGP (Указываем свой локальный ASN 65000)
1. #Priv router bgp 65000
# 2. Назначение Router ID (Чтобы не зависеть от падений физических интерфейсов)
2. #Priv bgp router-id 10.255.255.1

# 3. Объявление соседа (IP провайдера и его ASN)
3. #Priv neighbor 203.0.113.2 remote-as 64512
# 4. [Опционально] Пароль для защиты TCP сессии (MD5)
4. #Priv neighbor 203.0.113.2 password Secr3tKey

# 5. Анонсирование своих сетей в интернет
# ВАЖНО: Сеть с точной маской ОБЯЗАНА существовать в локальной таблице маршрутизации,
# иначе BGP откажется ее анонсировать (Правило точного совпадения).
5. #Priv network 192.0.2.0 mask 255.255.255.0

# 6. Применение политик (Route-map для манипуляции атрибутами входящего трафика)
6. #Priv neighbor 203.0.113.2 route-map SET-LOCAL-PREF in

# 7. Мягкая перезагрузка процесса (Soft Reset) после изменения политик
7. #Priv clear ip bgp * soft
```
